# Supported providers & parity matrix

Hive agents are not locked to Anthropic. An agent's `model` field selects the provider: a bare model id (no `/`) routes to Claude; a `<provider>/<model>[:<effort>]` prefix routes elsewhere. An unrecognized prefix falls back to Claude rather than failing the turn.

There are two lanes behind that routing:

**Lane A — passthrough (`kimi/...`, `deepseek/...`).** These providers run the full Claude runtime end to end: same adapter, same tool wiring, same skills and memory, same session mechanics. Only the network endpoint, the credential, and the default model differ, resolved per spawn. Because the underlying runtime is identical to Claude's, Lane A tracks Claude's column for most capabilities; where it differs (for example tool-search disabled, an effort-level clamp, no Anthropic server-side tools, cold vendor prompt cache on resume and its cache economics, nominal cost reporting, and validation status), the difference is called out in its row.

**Lane B — native provider loops (`openai/...`, `gemini/...`, `codex/...`).** These providers run their own bounded tool-calling loop against the vendor's native API, executing real hive tools through a tool bridge that sits inside hive (not inside each adapter). They get the same prompt assembly, the same skills, the same memory, and most of the same tool surface as Claude — with a documented, capped set of differences, captured cell by cell below.

## Cell legend

- **`full`** — capability works exactly as on Claude, no documented delta.
- **`caveat(note)`** — capability works, with a documented delta. The note is a short in-table tag; longer substance moves to a footnote.
- **`claude-only`** — capability does not exist on this provider; omitted deliberately and, where it matters at runtime, logged rather than silently dropped.
- **`n/a`** — the row's concept does not apply to this provider/column.

## Footnotes

[^4]: **Builtins.** openai/gemini/codex run hive-native implementations of Bash/Read/Write/Edit/Glob/Grep rather than the SDK's own builtins. Three documented deltas: Read is text-only — no images, PDFs, or notebooks; Grep is a JS-regex subset, not full ripgrep; Bash's working directory and environment do not persist across calls.
[^5]: **Server-side tools.** Lane A's caveat is scoped to Anthropic's own server-side WebFetch/WebSearch, which don't exist on the vendor-compatible endpoints. MCP-based substitutes — brave-search, browser via CDP — remain available on Lane A.
[^6]: **Tool surface limits & honesty.** Lane A forces tool-search deferral off (eager schema loading only). Lane B providers impose a 128-tool cap: a pinned tier (the core builtins, the skill loader, and the delegate Task tool) is never dropped; the remaining MCP-discovered tools tail-drop in inventory order when the cap is exceeded, and every drop is logged as an omission rather than silently disappearing. Tool-search deferral does not apply to Lane B — it builds its own bounded inventory per spawn. Cross-row honesty note: the toolkit section of the prompt renders from the assembly-time tool inventory, while the underlying server connects happen at bridge time and are fail-soft — a server listed in the prompt can be transiently absent for one turn if its connect fails, and that absence is logged.
[^8]: **Memory.** All five columns get hot-tier injection, structured recall, and FS-tier memory. The one documented delta is cosmetic: the model-visible name for the structured-recall tool differs by surface — Lane B teaches the fully-qualified tool name, while the Claude runtime surface (used by both the `claude` column and Lane A, since Lane A runs the same runtime) keeps the prompt trailer's bare short name (the callable tool is always the qualified name; this is a documented imprecision in that prompt trailer, not a functional gap). The qualified name taught to Lane B is a staleness edge if that tool is ever renamed without updating the trailer. Reflection scheduling (post-quiescence debounce) is provider-agnostic.
[^9]: **Guardrails.** Archetype PreToolUse guardrails are fully enforced on Lane B as a fail-closed gate wrapping every bridged tool execution — first-deny-wins, a thrown guardrail counts as a deny, and an assembly failure denies all tools; there is no bypass path, since hive executes every tool client-side. PreCompact has no Lane B analog (no Claude-style compaction on these lanes).
[^10]: **Session resume & continuity.** *openai* — durable resume chains a provider-issued response handle that is rewritten every turn; the handle horizon (7 days) is comfortably inside the provider's own retention window, so a live thread's handle is effectively never-expired; truncation is enabled as openai's compaction analog. A stale or expired handle self-heals via one fresh-context retry, breaker-invisible, at the cost of one exchange of prior context; organizations under zero-data-retention policies cannot use chained resume at all. Closure of the retry's edge cases is unit-tested only, not yet exercised against a live stale handle. *gemini* — durable resume works the same way via its own provider-issued handle; the handle horizon (7 days) sits comfortably inside the paid tier's 55-day retention, but the **free tier retains only one day**, so a free-tier thread left idle past a day self-heals to daily fresh context via the same path. Stale-handle detection is a hive-owned deterministic check. There is no truncation analog — an oversized context lands in a self-heal chain restart instead. *codex* — the codex backend does not support durable server-side handles at all, so hive itself persists and replays turn history client-side (including encrypted reasoning content); the replay history is whole-turn-trimmed under a roughly 200,000-character budget (not a per-turn cap), with a 7-day retention window. If a first-round reply is rejected outright on a non-empty replay, hive clears the stored history and retries once with a fresh context. A deliberate divergence: a turn budget of zero rounds short-circuits to an immediate no-op result with no network calls at all. *All columns* — reassigning an agent to a different provider always starts a fresh session with a short handoff annotation recorded in memory (no cross-provider history carry, ever); a codex-to-elsewhere handoff also clears the replayed history.
[^11]: **Subagents.** Lane B synthesizes one Claude-shaped delegate tool from the calling agent's configured delegate capabilities, restricted to a fixed enum of delegate roles; executing it runs a nested same-provider turn (its own delegate prompt, its one capability server plus the core builtins, a bounded turn budget) through a manager-owned runner — budget-accounted against the agent's spawn budget (requires `spawnBudget ≥ 2`; the default of 5 is fine), exempt from the per-thread lock, chained to the parent's abort, one level deep only, without its own session or history, and never able to trip a provider breaker (a nested fault surfaces as ordinary tool output text to the parent). Nested turns do not appear in the live active-spawn count; they surface through the saturation counter and the completion log instead. General-purpose subagents (an arbitrary free-form role, not a preconfigured delegate) remain `claude-only`. One provisioning note applies to every lane symmetrically: a delegate whose capability depends on a not-yet-provisioned per-agent account simply won't synthesize until that account exists — expected behavior, not a bug.
[^12]: **Reasoning-effort tuning.** Claude's per-turn effort classifier is catalog-driven and Claude-only; every non-Claude column instead uses the model string's static `:effort` suffix (see also Ruled non-goals). *Lane A* clamps the suffix to three levels (`low`/`medium`/`high`); anything else warns once and is dropped. An effort suffix given without a model (e.g. `kimi/:high`) parses `:high` as the model id itself, which the vendor rejects with a 4xx — a vendor-side configuration error, not a hive defect. *openai* currently parses the suffix out of the route but has no delivery channel to the provider yet — today it has no practical effect. *gemini* maps the suffix onto its native thinking-level setting: `none` coerces to `minimal` and `xhigh` coerces to `high`, each with a one-time warning. *codex* passes the suffix straight through as a reasoning-effort request field; critically, encrypted reasoning content is only requested and replayed when an `:effort` suffix is present — an effort-less codex agent still functions, but loses the benefit of replayed reasoning across turns.
[^15]: **Ops integration.** The circuit breaker, the honest-outage queue, and telemetry attribution are `full` on every column — they key on the resolved route provider (an outage on kimi only trips the kimi breaker; a tool or assembly fault never trips any breaker; timing metrics exclude tool execution time on every tool-executing lane). The caveats in this row scope narrowly to usage/cost reporting: Lane A reports a nominal cost computed with Claude's own pricing math (it is, after all, running the Claude runtime); openai currently reports zero for every token count (a known gap, flagged as a follow-up candidate); gemini and codex report zero cost (subscription/API billing is out of scope for cost telemetry) but accurate real token counts.
[^16]: **Auth & credentials.** Claude and codex both authenticate via subscription OAuth — no API key in the loop. Lane A resolves a per-provider API key from the environment, falling back to the local credential store; a credential rotation takes effect on the provider's next spawn, and a missing key fails as a config error that never touches the breaker. Kimi's default endpoint and model are the Moonshot Anthropic-compatible endpoint and `kimi-k3`; Deepseek's are the Deepseek Anthropic-compatible endpoint and `deepseek-v4-pro`. openai is API-key-only today, read from the instance's environment file with no credential-store integration yet — a missing key fails the turn as an honest outage. gemini resolves its API key from the environment first, falling back to Honeypot-backed Keychain storage like other vendor keys (not `.env`-only); a free-tier key trains on submitted data, so production traffic requires a paid-tier key, and there is no Google Cloud Vertex path.

## Ruled non-goals

1. **Translation proxies** (community LiteLLM-style routers, `claude-code-router`, and similar) are not a supported way to reach Lane A in production. Anything sitting between hive and the vendor endpoint is an unowned middlebox in the credential and fidelity path; only vendor-operated, Anthropic-compatible endpoints qualify.
2. **Carrying conversation history across a provider change.** Reassigning an agent's model to a different provider always starts a fresh session; a short memory-handoff annotation is the continuity bridge, not a transcript carry-over. (Codex additionally clears any replayed turn history it was holding.)
3. **Catalog-driven, per-turn effort tuning for non-Claude models.** Foreign models get the static `:effort` suffix on the model string; the adaptive effort classifier stays a Claude-lane capability.

## Out of scope (epic rulings)

- **Voice is pinned to the Claude lane, by code.** A voice-enabled agent configured with a non-Claude model still runs its voice turns on the engine's default Claude model. This is a documented caveat on voice-enabled agents today, and a candidate for revisit once the matrix has been live for a while.
- **OpenAI-compatible "sidecar" providers** for non-agentic, one-shot LLM calls elsewhere in the engine are a separate concern from this matrix, which covers agent turns only.
- **Gemini's managed-agent offering** (a preview capability at time of writing) is not a design target here.
- **Cross-provider cost/pricing normalization** beyond what each column's existing telemetry already reports.

### Revisit triggers

- Session retention needs grow past the current durable-resume horizon, or a continuity requirement longer than that horizon shows up — re-evaluate a provider-native conversation-history API as a new piece of work, not a patch to this matrix.
- A provider's newer agentic API ships on a cloud-platform-hosted auth surface it doesn't support today — re-evaluate that auth path as new work.
- A provider currently reached only via subscription OAuth begins serving its native agentic API under that same subscription auth. Concretely: if OpenAI's API surface becomes usable under subscription auth (the way codex's backend is today), revisit the OpenAI key-conditioned items as new work — not a re-add of the Conversations API path this epic deliberately left unused.
- Any future Lane B provider that genuinely has no tool access must explicitly re-declare that state rather than silently inheriting "tools executable" as a default.
