# Supported providers & parity matrix

Hive agents are not locked to Anthropic. An agent's `model` field selects the provider: a bare model id (no `/`) routes to Claude; a `<provider>/<model>[:<effort>]` prefix routes elsewhere. Provider plugins (KPR-394) extend the prefix set: a plugin installed via `hive plugin add` can register one additional provider id, routed exactly like a built-in. A prefix that no built-in and no installed plugin declares falls back to Claude rather than failing the turn; a **declared** provider that failed to load (ABI mismatch, missing compiled entry, throwing factory) instead fails its turns with an honest error — never a silent Claude fallback.

There are two lanes behind that routing:

**Lane A — passthrough (`kimi/...`, `deepseek/...`).** These providers run the full Claude runtime end to end: same adapter, same tool wiring, same skills and memory, same session mechanics. Only the network endpoint, the credential, and the default model differ, resolved per spawn. Because the underlying runtime is identical to Claude's, Lane A tracks Claude's column for most capabilities; where it differs (for example tool-search disabled, an effort-level clamp, no Anthropic server-side tools, cold vendor prompt cache on resume and its cache economics, nominal cost reporting, and validation status), the difference is called out in its row.

**Lane B — native provider loops (`openai/...`, `gemini/...`, `codex/...`, `grok/...`).** These providers run their own bounded tool-calling loop against the vendor's native API, executing real hive tools through a tool bridge that sits inside hive (not inside each adapter). They get the same prompt assembly, the same skills, the same memory, and most of the same tool surface as Claude — with a documented, capped set of differences, captured cell by cell below. Grok's "native API" is the operator-hosted CLIProxyAPI gateway's OpenAI chat-completions surface, not xAI's endpoint directly (footnote 16).

## Cell legend

- **`full`** — capability works exactly as on Claude, no documented delta.
- **`caveat(note)`** — capability works, with a documented delta. The note is a short in-table tag; longer substance moves to a footnote.
- **`claude-only`** — capability does not exist on this provider; omitted deliberately and, where it matters at runtime, logged rather than silently dropped.
- **`n/a`** — the row's concept does not apply to this provider/column.

## Footnotes

[^4]: **Builtins.** openai/gemini/codex/grok run hive-native implementations of Bash/Read/Write/Edit/Glob/Grep rather than the SDK's own builtins. Three documented deltas: Read is text-only — no images, PDFs, or notebooks; Grep is a JS-regex subset, not full ripgrep; Bash's working directory and environment do not persist across calls.
[^5]: **Server-side tools.** Lane A's caveat — kimi and deepseek alike — is scoped to Anthropic's own server-side WebFetch/WebSearch, which don't exist on the vendor-compatible endpoints. MCP-based substitutes — brave-search, browser via CDP — remain available on Lane A.
[^6]: **Tool surface limits & honesty.** Lane A forces tool-search deferral off (eager schema loading only) on both of its providers. Lane B providers impose a 128-tool cap: a pinned tier (the core builtins, the skill loader, and the delegate Task tool) is never dropped; the remaining MCP-discovered tools tail-drop in inventory order when the cap is exceeded, and every drop is logged as an omission rather than silently disappearing. Tool-search deferral does not apply to Lane B — it builds its own bounded inventory per spawn. Cross-row honesty note: the toolkit section of the prompt renders from the assembly-time tool inventory, while the underlying server connects happen at bridge time and are fail-soft — a server listed in the prompt can be transiently absent for one turn if its connect fails, and that absence is logged.
[^8]: **Memory.** All six columns get hot-tier injection, structured recall, and FS-tier memory. The one documented delta is cosmetic: the model-visible name for the structured-recall tool differs by surface — Lane B teaches the fully-qualified tool name, while the Claude runtime surface (used by both the `claude` column and Lane A, since Lane A runs the same runtime) keeps the prompt trailer's bare short name (the callable tool is always the qualified name; this is a documented imprecision in that prompt trailer, not a functional gap). The qualified name taught to Lane B is a staleness edge if that tool is ever renamed without updating the trailer. Reflection scheduling (post-quiescence debounce) is provider-agnostic.
[^9]: **Guardrails.** Archetype PreToolUse guardrails are fully enforced on Lane B as a fail-closed gate wrapping every bridged tool execution — first-deny-wins, a thrown guardrail counts as a deny, and an assembly failure denies all tools; there is no bypass path, since hive executes every tool client-side. PreCompact has no Lane B analog (no Claude-style compaction on these lanes).
[^10]: **Session resume & continuity.** *Lane A (kimi, deepseek)* — the Claude CLI's session ids are local transcript handles independent of the vendor endpoint, so resume replays the transcript client-side against a cold vendor prompt cache (re-billed tokens). *openai* — durable resume chains a provider-issued response handle that is rewritten every turn; the handle horizon (7 days) is comfortably inside the provider's own retention window, so a live thread's handle is effectively never-expired; truncation is enabled as openai's compaction analog. A stale or expired handle self-heals via one fresh-context retry, breaker-invisible, at the cost of one exchange of prior context; organizations under zero-data-retention policies cannot use chained resume at all. Closure of the retry's edge cases is unit-tested only, not yet exercised against a live stale handle. *gemini* — durable resume works the same way via its own provider-issued handle; the handle horizon (7 days) sits comfortably inside the paid tier's 55-day retention, but the **free tier retains only one day**, so a free-tier thread left idle past a day self-heals to daily fresh context via the same path. Stale-handle detection is a hive-owned deterministic check. There is no truncation analog — an oversized context lands in a self-heal chain restart instead. *codex* — the codex backend does not support durable server-side handles at all, so hive itself persists and replays turn history client-side (including encrypted reasoning content); the replay history is whole-turn-trimmed under a roughly 200,000-character budget (not a per-turn cap), with a 7-day retention window. If a first-round reply is rejected outright with a client-error (4xx) status on a non-empty replay, hive clears the stored history and retries once with a fresh context; server-side (5xx) and network faults get no retry and no history clear — they keep their full circuit-breaker weight. *grok* — the same stateless-replay model as codex, minus codex's own quirks: hive persists and replays turn history client-side against the operator-hosted gateway, whole-turn-trimmed under the same roughly 200,000-character budget with the same 7-day retention window, but with no 4xx self-heal at all (grok's replayed items are plain chat messages hive composed itself, so a 4xx on them is a real request-shape bug, not the backend's own inconsistency — heal-by-clear would mask it rather than fix it), and no encrypted-reasoning content to replay (grok has none). A deliberate divergence, pinned identically across codex, gemini, and grok: a turn budget of zero rounds short-circuits to an immediate max-turns error result with no network calls at all. The turn budget itself comes from the agent definition's `maxTurns` — the same field the Claude lane honors — where each model round (including every tool-call batch) consumes one unit; the adapters' internal 10-round default is a last-resort fallback for calls that supply no limit, not the operative ceiling. The same limits object carries the agent definition's `timeoutMs` (5-minute default — the Claude lane's own default), honored on all four Lane B columns as a wall-clock turn deadline: expiry aborts the in-flight round (and signals any in-flight tool call) mid-flight rather than waiting for a round boundary, since the round budget bounds round count, not round duration. A deliberate divergence from the Claude lane's deadline semantics: because a Lane B turn's wall clock folds hive-side tool execution time in, a deadline expiry surfaces as a turn-shape error (like a max-turns exhaustion) that is **inconclusive** to circuit-breaker accounting in both directions — it never counts toward a trip (a slow-but-healthy tool must not take a healthy provider offline) but also never counts as proof of provider health (it neither resets a provider's fault streak nor closes a half-open circuit, so a genuinely hung provider still trips on its real faults) — and it never enters the outage queue. The deadline bounds each spawn attempt; the manager's rare one-shot self-heal retries (auth rebuild, stale handle) can at most double a turn's total wall clock. `budgetUsd` remains inert on Lane B. *All columns* — reassigning an agent to a different provider always starts a fresh session with a short handoff annotation recorded in memory (no cross-provider history carry, ever); a codex- or grok-to-elsewhere handoff also clears the replayed history.
[^11]: **Subagents.** Lane B synthesizes one Claude-shaped delegate tool from the calling agent's configured delegate capabilities, restricted to a fixed enum of delegate roles; executing it runs a nested same-provider turn (its own delegate prompt, its one capability server plus the core builtins, a bounded turn budget) through a manager-owned runner — budget-accounted against the agent's spawn budget (requires `spawnBudget ≥ 2`; the default of 5 is fine), exempt from the per-thread lock, chained to the parent's abort, one level deep only, without its own session or history, and never able to trip a provider breaker (a nested fault surfaces as ordinary tool output text to the parent). Nested turns do not appear in the live active-spawn count; they surface through the saturation counter and the completion log instead. General-purpose subagents (an arbitrary free-form role, not a preconfigured delegate) remain `claude-only`. Lane A is unaffected by all of this — it runs the SDK's own subagent machinery, pinned to the foreign model. One provisioning note applies to every lane symmetrically: a delegate whose capability depends on a not-yet-provisioned per-agent account simply won't synthesize until that account exists — expected behavior, not a bug.
[^12]: **Reasoning-effort tuning.** Claude's per-turn effort classifier is catalog-driven and Claude-only; every non-Claude column instead uses the model string's static `:effort` suffix (see also Ruled non-goals). *Lane A* clamps the suffix to three levels (`low`/`medium`/`high`); anything else warns once and is dropped. An effort suffix given without a model (e.g. `kimi/:high`) parses `:high` as the model id itself, which the vendor rejects with a 4xx — a vendor-side configuration error, not a hive defect. *openai* currently parses the suffix out of the route but has no delivery channel to the provider yet — today it has no practical effect. *gemini* maps the suffix onto its native thinking-level setting: `none` coerces to `minimal` and `xhigh` coerces to `high`, each with a one-time warning. *codex* passes the suffix straight through as a reasoning-effort request field; critically, encrypted reasoning content is only emitted by the backend — and thus replayed — when an `:effort` suffix is present — an effort-less codex agent still functions, but loses the benefit of replayed reasoning across turns. *grok* passes the suffix straight through as the chat-completions `reasoning_effort` field, delivered verbatim across all four levels including `xhigh` — the Lane A clamp that dropped it is gone, so grok's native top reasoning tier is expressible for the first time; `minimal`/`none` coerce to `low` instead (chat completions has no "off" lever), warned once per (agent, effort).
[^15]: **Ops integration.** The circuit breaker, the honest-outage queue, and telemetry attribution are `full` on every column — they key on the resolved route provider (an outage on kimi only trips the kimi breaker, an outage on grok only trips the grok breaker; a tool or assembly fault never trips any breaker; a Lane B wall-clock deadline expiry — see footnote 10 — likewise never trips, and is deliberately inconclusive rather than exculpatory: it neither resets a fault streak nor closes a half-open circuit; timing metrics exclude tool execution time on every tool-executing lane). Every Lane B adapter is single-attempt at the HTTP layer by design: vendor-SDK internal retries are pinned off (gemini `maxRetries: 0`, codex raw fetch, grok raw fetch through the gateway, openai `maxRetries: 0` since 2026-08-25 — openai-node's default of two silent backoff retries on 429/5xx was in effect until then), so the first provider fault reaches breaker classification undiluted and turn timing is never inflated by hidden retry backoff; retry policy lives entirely in the breaker/outage-queue layer. The caveats in this row scope narrowly to usage/cost reporting: Lane A reports a nominal cost computed with Claude's own pricing math (it is, after all, running the Claude runtime); openai currently reports zero for every token count (a known gap, flagged as a follow-up candidate); gemini, codex, and grok report zero cost (subscription/API billing is out of scope for cost telemetry) but accurate real token counts.
[^16]: **Auth & credentials.** Claude and codex both authenticate via subscription OAuth — no API key in the loop. Lane A resolves a per-provider API key from the environment, falling back to the local credential store; a credential rotation takes effect on the provider's next spawn, and a missing key fails as a config error that never touches the breaker. Kimi's default endpoint and model are the Moonshot Anthropic-compatible endpoint and `kimi-k3`; Deepseek's are the Deepseek Anthropic-compatible endpoint and `deepseek-v4-pro`. **Grok routes through an operator-hosted gateway, not xAI's endpoint directly (KPR-384; grok itself promoted to a native Lane B adapter in KPR-392).** xAI's Anthropic-compatible `/v1/messages` validator rejects any tool `input_schema` that omits the `required` array — valid JSON Schema, accepted by Anthropic, and emitted by more than a dozen of the Claude CLI's builtin/plugin tools — so a direct spawn 400s on every realistic toolkit; that history is why the gateway pattern exists, even though `GrokGatewayAdapter`'s own chat-completions call shape no longer goes anywhere near that validator — and separately, ToolBridge's `normalizeSchema` (`tool-bridge.ts:538`) already fills `required: []` on every bridged schema, so the quirk is structurally impossible on the Lane B path regardless of endpoint. `GrokGatewayAdapter` therefore pins its base URL to a self-hosted, loopback-only CLIProxyAPI gateway (default `http://127.0.0.1:8317`; non-secret `GROK_GATEWAY_URL` override, validated per spawn — https, or http to loopback only, since the override redirects both the credential and the conversation stream; version-pinned by the operator) that fronts the vendor's OpenAI-format backend. Hive's credential is `GROK_GATEWAY_KEY` — an entry from the gateway config's `api-keys` allowlist, resolved per spawn by the manager's own grok arm (`resolveGrokModuleSlice`) on the same env → Honeypot chain kimi/deepseek use via `resolvePassthroughSpawn`, rotated with `hive credentials add`, and failing as the same breaker-invisible config fault. The **gateway** owns the `grok login` subscription OAuth session (six-hour access token, rotating refresh token) and its refresh lifecycle; the operator still runs `grok login` once per machine, but hive itself never reads, refreshes, or writes `~/.grok/auth.json` — the KPR-371 in-hive OAuth machinery stays removed, keeping the blast radius of a leaked hive-side credential at a loopback gateway key rather than an account-scoped OAuth token. The subscription session exposes only `grok-4.6` (default) and `grok-4.5`; the API's wider catalogue is not reachable under this auth. openai is API-key-only today, read from the instance's environment file with no credential-store integration yet — a missing key fails the turn as an honest outage. gemini resolves `GEMINI_API_KEY` from the environment first, falling back to Honeypot-backed Keychain storage — but that resolution happens once at engine start, so seeding or rotating the key requires a service restart to take effect (unlike Lane A's per-spawn resolution); the `GOOGLE_GENAI_API_KEY`/`GOOGLE_API_KEY` fallbacks are environment-only, never Keychain-resolved. A free-tier key trains on submitted data, so production traffic requires a paid-tier key, and there is no Google Cloud Vertex path.

## Plugin-registered providers (KPR-394)

A hive plugin can register one Lane B provider: a `provider:` block in `plugin.yaml` names the model-prefix id and a compiled entry exporting `createProviderModule(kit)`; the engine loads it at boot (plugin install/remove already restart the service — there is no hot load or unload, and SIGUSR1 never touches provider code). What the class guarantees, and what it does not:

- **Execution path:** the full Lane B surface — real prompt assembly, tool execution over the hive tool bridge (generic `laneB` tool-compatibility column), fail-closed guardrails, delegate subagents, and the shared implementation layer (scaffold, bounded dispatch loop, SSE framing) injected by the engine at load time, so shared fixes cover plugin providers without a plugin release.
- **Sessions:** per the manifest's declared semantics (`stateless-replay` on hive-persisted turn history, or `server-resumable` handle chaining). Caveat: the manager's stale-handle self-heal matchers are openai/gemini-specific — a plugin provider's stale handle surfaces as an ordinary error turn; backends that need healing implement it in-adapter (codex precedent).
- **Effort:** the `:effort` suffix parses generically and is delivered raw on the route; mapping/coercion/warn-once is the module's job (grok/gemini precedents).
- **Ops:** breaker, honest-outage queue, and telemetry key on the provider id automatically — a plugin provider gets its own breaker, its own outage episodes, and its own heartbeat rows. Classification fidelity is an authoring obligation: decorate transport errors with status prefixes, or degrade only your own breaker's evidence. Config faults (missing key, invalid base URL, broken provider) are breaker-invisible. `costUsd` reports 0 unless the module reports real costs; token counts are whatever the module accumulates.
- **Auth:** the manifest names an `api-key-env`; the engine resolves it per spawn on the standard env → Honeypot chain (`hive credentials add <KEY>`), and validates any `base-url-env` override (https, or http to loopback only). The key must be vendor-distinct: naming a curated engine credential key (`ANTHROPIC_API_KEY`, `GROK_GATEWAY_KEY`, `KIMI_API_KEY`, …) is rejected at `hive plugin add` and leaves the provider declared-broken at boot — a plugin provider is never handed a sibling's credential. Modules never touch env or Keychain.
- **ABI:** the manifest's `abi:` integer must exactly equal the engine's `LANE_B_PROVIDER_ABI_VERSION` (currently 1); mismatch in either direction leaves the provider declared-broken (honest per-turn failures, doctor-visible) — as does a missing compiled entry, an id collision (first registration wins), or a throwing factory — of which only the throwing factory is invisible to doctor, whose audit is static (manifest-derived); it surfaces in engine logs and per-turn errors instead. Compile-time types ship as the `@keepur/hive/provider-abi` subpath export (devDependency; types-only).
- **Not guaranteed:** the engine does not validate the vendor surface behind a plugin provider — row-17-equivalent validation status is the plugin's claim, not the engine's. Third-party providers never get rows in this matrix; a provider plugin's README must carry a parity statement covering this matrix's row set (tools, sessions, effort, auth, validation status), enforced at registry-curation tier (DOD-212: provider plugins run in-process and install through curated registries only).

Authoring in brief: **extend the kit's scaffold** (the wall-clock deadline, exception containment, and usage accounting only bound your adapter if you do), keep history wiring primary-context-only, pick a vendor-distinct id and a vendor-distinct credential key (built-in ids and aliases are reserved, as are the curated engine credential keys), and route errors through status-prefixed decorations.

## Ruled non-goals

1. **Translation proxies** (community LiteLLM-style routers, `claude-code-router`, and similar) are not a supported way to reach Lane A in production. Anything sitting between hive and the vendor endpoint that the operator does not own is an unowned middlebox in the credential and fidelity path; vendor-operated, Anthropic-compatible endpoints are the rule for Lane A's remaining two providers (kimi, deepseek). Grok carries the one sanctioned exception forward from its Lane A days (KPR-384), now on its native Lane B adapter (KPR-392): xAI's own compat endpoint rejects tool schemas that omit the `required` array, 400-ing every realistic toolkit, so grok fronts an **operator-hosted, loopback-only** CLIProxyAPI gateway — the operator owns the middlebox, its pinned version, and the credential it holds, which is what the non-goal actually guards, Lane A or Lane B.
2. **Carrying conversation history across a provider change.** Reassigning an agent's model to a different provider always starts a fresh session; a short memory-handoff annotation is the continuity bridge, not a transcript carry-over. (Codex additionally clears any replayed turn history it was holding.)
3. **Catalog-driven, per-turn effort tuning for non-Claude models.** Foreign models get the static `:effort` suffix on the model string; the adaptive effort classifier stays a Claude-lane capability.

## Out of scope (epic rulings)

- **Voice is not provider-pinned — keep voice-enabled agents on Claude-lane models.** A voice-enabled agent configured with a non-Claude model runs its voice turns on that configured provider, and that path is unsupported: latency, session semantics, and prompt-assembly behavior for live calls are validated only on the Claude lane. A code-enforced Claude-lane pin for voice was considered and deliberately deferred as a standalone piece of future work; until it (or a proper voice-on-other-lanes validation) ships, the supported configuration is a Claude-lane model on every voice-enabled agent.
- **OpenAI-compatible "sidecar" providers** for non-agentic, one-shot LLM calls elsewhere in the engine are a separate concern from this matrix, which covers agent turns only.
- **Gemini's managed-agent offering** (a preview capability at time of writing) is not a design target here.
- **Cross-provider cost/pricing normalization** beyond what each column's existing telemetry already reports.

### Revisit triggers

- Session retention needs grow past the current durable-resume horizon — concretely, a session TTL or thread-continuity requirement beyond 30 days, the point where the chaining ruling's retention arithmetic inverts — re-evaluate a provider-native conversation-history API as a new piece of work, not a patch to this matrix.
- A provider's newer agentic API ships on a cloud-platform-hosted auth surface it doesn't support today — re-evaluate that auth path as new work.
- A provider currently reached only via subscription OAuth begins serving its native agentic API under that same subscription auth. Concretely: if OpenAI's API surface becomes usable under subscription auth (the way codex's backend is today), revisit the OpenAI key-conditioned items as new work — not a re-add of the Conversations API path this epic deliberately left unused.
- Any future Lane B provider that genuinely has no tool access must explicitly re-declare that state rather than silently inheriting "tools executable" as a default.
- **Grok cost attribution.** Whether subscription-OAuth traffic reaching xAI (via the self-hosted gateway since KPR-384) draws against the subscription pool or an API-credit balance is undocumented by the vendor. It returned success on an account with no API credits purchased, which implies the subscription pool, but that is an inference, not a contract. If a credit balance ever starts moving, revisit row 15's Grok cell as new work.
