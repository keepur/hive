# KPR-463 — Deploy the engine and voice worker from the instance package

## TL;DR

Extend Hive's existing npm package and per-instance `.hive` lifecycle so an enabled LiveKit voice worker ships, installs, starts, updates, and rolls back with the engine. Dodi's deployment must ultimately use instance-owned artifacts and dependencies, with verified service paths, release identity, bridge authentication, LiveKit registration, restart, rollback, and preservation of operator state; writing or implementing this spec alone does not complete that migration. This specification authorizes no deployment or live call during maturation.

## Key Points

- Ship `pkg/voice-worker.min.js` in `@keepur/hive`, keep the LiveKit/native packages external to the bundle, and install their pinned production dependency tree inside `.hive/node_modules`.
- Reuse `.hive.next`, `.hive`, `.hive.prev`, and `.hive.broken`; engine and enabled worker form one release unit. Planned rotation requires reversible admission quiescence before signaling either service; a timeout defers the rotation.
- Stray writers are made harmless, not proven absent (May, 2026-09-14): every artifact job — fetch/`npm pack`, extraction, `npm ci`, packaged probes — runs under macOS Seatbelt (`/usr/bin/sandbox-exec`) confined to its own single-use job directory, and a job directory is never promoted; `.hive.next` is an APFS clone (`cp -c`, full copy on non-APFS) taken after the direct child exits successfully and verified before rotation. No descendant-process accounting, census, guardian, or receipt machinery is required; `sandbox-exec` is a fail-closed host prerequisite.
- Keep `hive.yaml`, `.env`, Honeypot credentials, agent data, plugins, skills, logs, and `.hive-state` outside the replaceable package. Preserve Twilio → LiveKit → Deepgram/Cartesia and Mokie's `voice-livekit` routing.
- An engine boot marker or worker heartbeat alone is insufficient: require both running service identities, authenticated bridge admission without a model turn, and current LiveKit registration health.
- Validate a real packed artifact with a fresh production install and native audio loading. A test that symlinks the development `node_modules` cannot satisfy this ticket.
- Scope operational migration to dodi. Preserve both pilot worktrees until verified migration and a usable rollback path exist; their retirement is a later cleanup action.
- KPR-466 consumes the deployment evidence described below and owns caller-perceived end-to-end acceptance. No latency target, warm-path default, vendor rollout, or telephony provisioning is selected here.
- ⚠ Delegated choices: one npm package, publishable dependency lock, macOS/Apple Silicon on Node 24 as the deployment acceptance host, and a per-instance loopback worker health port. These choices need review through the child workflow, but no human question blocks drafting.

### Problem

Dodi's engine runs `pkg/server.min.js` from `/Users/mokie/github/kpr-320-live-call`, and `com.hive.dodi.voice-worker` runs that checkout's `dist/voice-worker/main.js`. Its `node_modules` links to `/Users/mokie/github/kpr-320-work/node_modules`. Removing either development worktree can break the instance. A normal npm install/update cannot replace this arrangement today.

### Goals

1. A fresh supported install and an update supply both executable services and all runtime dependencies without a development checkout.
2. Both services demonstrably run the intended artifact/revision and the same unchanged instance identity/configuration.
3. Start, stop, update, restart, failed-update recovery, and rollback handle the enabled worker with the engine.
4. Dodi migrates to the supported layout with checked evidence and an exercised recovery path, while Keepur remains unaffected.

### Non-goals

No container/orchestrator adoption, separate worker product, multi-host rollout manager, general deployment journal, fleet migration, new automatic update policy, zero-downtime deployment, active-call migration, DB/schema migration, credential rotation, vendor changes, inbound rollout, SIP object creation, caller-ID/CNAM work, ambience, voice cloning, vendor A/B, or changes to warm execution and speech timing. KPR-321 retains its telephony operations; upstream designed SIP/P/W/T gates are not retrospectively passed by this work.

## 3. Artifact and dependency contract

### 3.1 One release unit

The existing `@keepur/hive` tarball gains `pkg/voice-worker.min.js`. The engine remains `pkg/server.min.js`, CLI remains `pkg/cli.min.js`, and `pkg/mcp/voice-livekit.min.js` remains the outbound MCP server. The production worker invocation is:

```text
<absolute node path> <instance>/.hive/pkg/voice-worker.min.js start
```

Bundle Hive-owned worker code using existing esbuild conventions. Externalize `@livekit/agents`, all currently imported LiveKit plugins, and `@livekit/rtc-node`, retaining their installed SDK process helpers, native libraries, and model assets. Do not bundle the SDK's dynamically located job/inference modules or copy platform binaries out of their packages. The existing `defineAgent` default export and symlink-safe main guard must work both when directly launched and when imported by a forked SDK process; importing the agent module must not launch a second supervisor.

Promote the six existing pinned LiveKit entries to production dependencies, preserving their current versions. ElevenLabs remains installed because `session.ts` imports it, without enabling or changing that vendor. Dependency pruning or lazy vendor loading is outside this ticket. The tradeoff is a larger production dependency installation even on voice-disabled instances; no worker starts or credential validation runs there.

### 3.2 Reproducible installation

Publish `npm-shrinkwrap.json` generated deterministically from the reviewed repository lockfile during packaging. Keep `package-lock.json` as the development source of truth and guard generated shrinkwrap equality; do not maintain two hand-edited dependency trees. Copy the shrinkwrap in every package-population path and install staged production dependencies with `npm ci --omit=dev` using the recorded deployment npm version and required native install scripts, inside a confined single-use job directory (§5.1). Reject a missing/inconsistent lock in artifacts that declare this new deployment contract. npm documents publishable shrinkwrap for deployed CLI/daemon applications, and `npm ci` fails a manifest/lock mismatch rather than rewriting the lock. [npm shrinkwrap](https://docs.npmjs.com/cli/v11/configuring-npm/npm-shrinkwrap-json/), [npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci/).

Reproducible means the same Hive artifact and locked dependency versions on the same supported OS/architecture/Node/npm environment. It does not promise bit-identical native compilation across machines or offline dependency installation. Record native/install prerequisites — including `/usr/bin/sandbox-exec` passing its preflight self-test, and an instance volume where the job directory can be promoted by APFS clone or, under the documented full-copy fallback, copied with sufficient free space — and fail before switching services when they are absent. Resume must rerun/verify a complete install after interruption; existence of `node_modules` alone is insufficient.

Accept a resolved npm release or an explicitly supplied local packed `.tgz` through `hive update --artifact=<absolute-path>` (mutually exclusive with `--tag`). The artifact option uses the same extraction, validation, dependency installation, staging, and health path; it permits testing and migrating a reviewed candidate without an npm publication or an implicit checkout fallback. Record its digest and source revision. Registry/tag failure must never silently substitute code from `BUILD_DIR`. The legacy multi-instance developer build mode may remain, but invoking a supported single-instance update must not read a build checkout or global instance registry.

First adoption must work when the installed CLI/deploy script does not understand this contract. Document a bootstrap from the validated candidate tarball into durable tooling under the instance's `.hive-state`: install its locked dependencies as a confined artifact job under §5.1, then clone the verified job output (`cp -c`, or the documented full-copy fallback) into a durable, non-job tooling area, `<instance>/.hive-state/tooling/<artifact-digest>/`, keyed on the candidate tarball's SHA-256 so re-running adoption for the same candidate is idempotent (an existing verified entry is reused, not reinstalled), and invoke that tooling's packaged CLI with explicit `HIVE_HOME`/`HIVE_CONFIG`. This tooling area is deliberately outside the single-use job-directory lifecycle: it is not disposed after the operation reports and not swept at the next operation's start, and it carries its own retention — an entry is removed only by an explicit cleanup step after the instance runs a packaged release that understands this contract, never by the ordinary job sweep. The tooling CLI must execute its own matching deployment implementation, not fall back to the old installed `.hive/service/deploy.sh`. The resulting live plists still point only to `.hive/pkg`, never to the tooling area. Because the tooling area is durable, the same verified tooling remains available through migration rollback/reapply, and tests must exercise this old-updater-to-new-artifact path.

### 3.3 Release identity

Ship `pkg/release.json` containing a small versioned manifest: package version, full source revision, dependency-lock digest, and worker artifact capability/path. Produce it from the build input, not the operator's working directory. A release/candidate with unknown or dirty provenance is ineligible for dodi migration. Record the tarball SHA-256 separately in deployment evidence; do not embed a self-referential archive digest.

At boot, both services log the same release identity plus component, PID, and boot identifier using `createLogger`. The worker supervisor also exposes this identity on its existing heartbeat; job counter updates must not overwrite supervisor identity or liveness. CLI/doctor output must distinguish installed artifact identity from the identity reported by the running processes. Preserve the existing engine startup markers used by deploy checks.

An offline worker diagnostic must verify version/manifest consistency, real imports of the production SDK/plugins/native RTC, and Silero model loading, then exit explicitly successful. It must not load operator secrets, connect Mongo/LiveKit, dispatch a room, start a model turn, or place a call. The implementation plan may choose a dedicated packaged helper rather than overload SDK CLI parsing. No `.ts`, `tsx`, global LiveKit installation, repository root, or development dependency can be necessary on the runtime path.

## 4. Instance and service contract

Use the existing instance home discovered by `resolveHiveHome`; dodi's intended root is `~/services/hive/dodi`, subject to read-back during the migration inventory. Both plists have that `WorkingDirectory`, explicit `HIVE_HOME`, and the same explicit `HIVE_CONFIG` selection when supplied. Preserve `HOME` for the current user's Keychain and the required operational `PATH`. Engine and worker resolve the same instance ID, Mongo database identity, bridge port/token, vendor configuration, and per-agent voices through the shared loader.

Store generated plists at `<instance>/service/com.hive.<id>.{agent,voice-worker}.plist`, linked from that user's LaunchAgents directory. Executable paths are absolute and point inside `.hive/pkg`; no generated production plist contains `src`, `dist`, a pilot checkout, `npx`, or a borrowed `node_modules`. Escape XML values and support spaces, ampersands, and symlinked instance homes. Verify canonical paths for containment without rejecting an intentional instance-home symlink whose target is outside development worktrees.

Preserve stable labels and per-instance logs. `hive start --daemon` installs/starts engine and, only when `voice.livekit.enabled === true`, worker. `hive stop` stops both target-instance labels, including a previously installed worker after voice has been disabled. Repeating start/stop is idempotent. With voice disabled, leave no enabled stale worker LaunchAgent that could return at login; ordinary engine use requires no voice keys or LiveKit connectivity. Foreground `hive start` keeps its existing engine behavior, with the separate worker command documented.

Use the SDK's existing health listener bound to `127.0.0.1`, with a deterministic per-instance port: `instance.ports.voiceWorker` override, otherwise `instance.portBase + 7`. Validate the port and collisions with the instance's other resolved listeners before service changes. This avoids the SDK-wide default port colliding across instances. The resolved port must be used consistently by worker options and lifecycle probes; a collision with another process fails without killing that process.

The pinned SDK supplies registration-aware `GET /` health and a `GET /worker` response with agent name and active job count. Use those facilities; no new public control server is needed. An HTTP 200 from `/worker` alone is not a readiness result. [LiveKit 1.6.4 worker](https://github.com/livekit/agents-js/blob/%40livekit%2Fagents%401.6.4/agents/src/worker.ts), [HTTP server](https://github.com/livekit/agents-js/blob/%40livekit%2Fagents%401.6.4/agents/src/http_server.ts).

Generated plists contain no credential values. Preserve `.env`/alternate dotenv files, Keychain namespaces, per-agent voice maps, Mokie's server inventory, agent model selection, and voice flags. Missing credentials are reported by key name, never value. Retain the env-first/Keychain-second shared loader behavior; do not add another secrets store or treat an interactive shell's exported keys as proof that launchd can resolve them.

Artifact jobs stage under `<instance>/.hive-state/jobs/<operation-id>/<job-id>/` — instance-owned state outside the replaceable package, on the same volume as `.hive` so promotion can be an APFS clone. The host prerequisites for every operation that runs an artifact job — init, resume, update, and first adoption — are `/usr/bin/sandbox-exec` (present and passing the §5.1 self-test) and a volume that supports `cp -c` cloning or, failing that, a full copy with enough free space; preflight reports which promotion method it will use. Neither prerequisite is needed to run the services, only to stage a new artifact. Ordinary `hive rollback` to `.hive.prev` (§5.2) promotes no new artifact and runs no confined job, so its preflight checks neither; the one recovery path that must keep working when everything else is broken does not depend on `sandbox-exec`.

## 5. Lifecycle and recovery

### 5.1 Update transaction

The single-instance lifecycle has these required phases, implemented by extending the existing helpers:

1. **Preflight and stage while current services stay up.** Resolve exactly one instance and acquire a per-instance operation lock. Validate destination paths, target identity, complete artifacts/dependencies, candidate runtime loading, configuration compatibility, and a usable prior-release recovery route. Capture existing target service definitions and enabled/loaded state outside `.hive`. Prevent concurrent start/stop/update/rollback or deploy-check operations from interleaving for this instance. Run the confinement self-test before the first artifact job. Stage through confined single-use job directories and promote only a verified clone into `.hive.next` (the artifact-job model below); candidate runtime loading is checked against that clone, never against a job directory.
2. **Establish reversible admission quiescence.** Before planned update/restart/rollback, check the running worker's registration-aware health, SDK active jobs, and existing call telemetry. An already active call or uncertain state defers the operation. For a packaged worker, request an operation-scoped maintenance barrier through instance-local IPC under `.hive-state`, identified by operation ID, supervisor PID, and boot ID. The supervisor must acknowledge that its request-admission gate is closed before an idle result is usable. Reject subsequent job requests without stopping existing jobs. Account for every request accepted before the barrier, including assignments and job launches still pending; an SDK active-job count of zero alone cannot establish quiescence. Keep both services running while these requests settle. Wait at most 30 seconds for closed admission, no unresolved accepted requests, and no active jobs. If a racing call outlasts that budget, a pending assignment remains unresolved, or the acknowledgement cannot be verified, abort **before any signal or bootout**, reopen admission on that same supervisor, verify the release acknowledgement, and report deferred. Preserve the call, engine, artifacts, and loaded service definitions. Do not introduce a force-call-termination flag.
3. **Stop worker, then engine, after quiescence.** With quiescence verified, use `launchctl bootout` while keeping the admission barrier closed until the old supervisor exits. This prevents `KeepAlive` from respawning processes during rotation. Keep the engine up until the worker supervisor has exited — verified by its PID exiting and its health listener releasing; verified quiescence already means it had no live SDK jobs, and a straggling SDK helper process is not a rotation hazard (it owns no instance listener, and the candidate tree is a verified clone no prior process holds open), so no descendant census is required — then stop the engine and verify its exit before moving files. Once shutdown has been signaled it is irreversible: a bounded stop failure enters checked recovery under step 5, rather than claiming that cancelling an SDK drain can preserve the old process. Never kill arbitrary port owners or other-instance PIDs. Record and reject unexpected owners. Automatic recovery from a failed candidate is allowed to stop the failed pair.
4. **Rotate and start.** Reuse `.hive.next → .hive`, with prior `.hive → .hive.prev`; `.hive.next` is only ever the verified clone written by the orchestrator, and no artifact job writes to it. Install the corresponding service definitions, start engine, verify its fresh boot, then start worker. A matching release identity and all enabled-service health checks in §6 are required before reporting success. Use bounded checks, retaining the existing engine retry budget (three 30-second windows with 10-second waits); apply an explicit bounded worker check budget of the same maximum. These are deployment timeouts, not call latency targets.
5. **Recover on any failure after stopping.** Fetch/install/preflight failure, a job's non-zero direct-child exit, or clone-verification failure leaves the prior pair running and disposes the job directory and any unverified clone. Swap, plist/link write, bootstrap, or health failure after shutdown enters recovery, even under shell `set -e`. Stop any candidate processes, restore the prior artifact and exact usable service definitions, start engine then prior worker, and check restoration. Report the failed deployment as failed even when recovery succeeds. If restoration fails, report both failure stages and retained recovery paths without claiming a healthy rollback.

The pinned SDK's SIGTERM handler catches drain errors and then closes the server; `drain()` sets a non-resettable draining state. Neither is a reversible maintenance probe. Use the supported job-request hook for the admission gate, with acceptance bookkeeping established before calling `JobRequest.accept()`. Its returned promise does not await assignment/launch in this SDK, so it cannot clear pending bookkeeping. Keep supervisor-owned accepted-request bookkeeping until completion is acknowledged by the Hive-owned agent entry/shutdown wrapper, keyed to the supervisor boot and job; combine that bookkeeping with SDK active-job health before declaring idle. An unassigned request or missing completion acknowledgement stays unresolved and defers maintenance. This bookkeeping covers LiveKit job requests inside the supervisor for call admission only; it is not process accounting, and no part of this transaction requires proving that the descendants of any process — the worker's SDK job/inference children or the artifact jobs below — have exited. Test this evidence path without patching SDK internals or changing conversation behavior. Local IPC needs no new public control server. On ordinary pre-signal failure, release the barrier and verify resumed admission; if that acknowledgement fails, report the unresolved maintenance state and retained services rather than claiming availability was restored. An interrupted operation retains enough ownership state for the next invocation to reconcile the barrier with the current boot before proceeding. [LiveKit 1.6.4 shutdown](https://github.com/livekit/agents-js/blob/%40livekit%2Fagents%401.6.4/agents/src/cli.ts#L73-L85), [worker drain and assignments](https://github.com/livekit/agents-js/blob/%40livekit%2Fagents%401.6.4/agents/src/worker.ts), [job acceptance](https://github.com/livekit/agents-js/blob/%40livekit%2Fagents%401.6.4/agents/src/job.ts).

The command executing the switch must survive replacement of its own `.hive/service` scripts: freeze the required orchestration code in the operation's instance-local temporary area before rotation or otherwise ensure no later code read uses a moved/deleted path. Clean up lock/staging state on ordinary failure. An interrupted operation must be detectable on the next invocation and refuse destructive rotation until its `.hive`/`.prev`/`.next` and service state are reconciled; a minimal operation marker is sufficient, not a general journal.

**Artifact-job model: write confinement and clone-on-promote.** This is the whole answer to stray build/install/packaging processes (May's decision of 2026-09-14, resolving the plan-feasibility blocker `JOB_ACCOUNTING_UNAVAILABLE`). The transaction never proves that a detached or reparented child of an artifact job has exited; it makes such a child unable to affect anything that is promoted.

- *Confinement.* Every artifact job — the registry fetch/`npm pack`, tarball extraction, `npm ci --omit=dev`, the §3.3 offline worker diagnostic and any other packaged probe, and the §3.2 bootstrap-tooling install — runs under `/usr/bin/sandbox-exec` with a Seatbelt profile that denies file writes everywhere except inside that job's own directory, `<instance>/.hive-state/jobs/<operation-id>/<job-id>/`, plus the device nodes stdio needs; reads, process execution, and network stay allowed. `npm_config_cache`, `TMPDIR`, and npm's log directory point inside the job directory. The kernel applies the profile to every descendant, including one spawned detached through an intermediate that has already exited and reparented to launchd. The frozen orchestration helper, `.hive.next`, `.hive`, `.hive.prev`, and the operator's home lie outside every job directory, so no job can modify them. Invoke `sandbox-exec` with an argv array from the frozen helper (no shell string); the helper stays builtin-only because `sandbox-exec` is a host binary, not a dependency.
- *Preflight self-test.* Before the first artifact job, run a confined probe that must fail with `EPERM` writing outside a scratch job directory and succeed writing inside it. A missing `/usr/bin/sandbox-exec`, or a self-test that does not deny, fails the operation closed before any staging or service change; there is no unconfined fallback. Apple deprecates `sandbox-exec` but ships it on macOS 26 — the self-test, not the binary's presence, is the standing guard, and the macOS version and self-test outcome are recorded in evidence.
- *Single-use job directories.* A job directory is created for one job, never reused, and never promoted or renamed into place. Disposal is deferred: dispose after the operation reports its result, and sweep leftovers at the start of the next operation. A straggler that keeps writing into a disposed tree affects nothing. The §3.2 bootstrap tooling is the one exception to disposal, and it is not an exception to this rule: its job directory is still disposed and never promoted, but its verified output is cloned out to the durable `<instance>/.hive-state/tooling/<artifact-digest>/` area with its own retention so that first-adoption rollback/reapply can reuse it.
- *Clone-on-promote.* After a job's direct child exits successfully, the orchestrator clones the job's output tree into `<instance>/.hive.next` with `cp -c` (APFS clone; the clone has its own inodes, so a write through a descriptor a straggler opened earlier lands in the job directory, not the clone). On a volume where cloning fails for lack of APFS support, fall back to a full copy; preflight announces the method and fixes it for the whole operation. Any non-zero exit from the promotion step itself — whichever method preflight selected, and for any reason (ENOSPC, EIO, a partial tree, not only APFS-unsupported) — discards the partial `.hive.next` and fails the operation into step 5 recovery before any service signal; the promotion method is never switched mid-operation. `.hive.next` is written only by this step.
- *Clone verification.* Verify the clone, reading the clone only: required entries present (`pkg/server.min.js`, `pkg/voice-worker.min.js`, `pkg/cli.min.js`, `pkg/mcp/`, `pkg/release.json`, `npm-shrinkwrap.json`, `package.json`); `pkg/release.json` package version and lock digest consistent with the fetched artifact digest recorded in the operation marker and with the clone's shrinkwrap; the installed dependency tree consistent with the lock (an `npm ls --omit=dev`-class check, run as its own confined job); and the candidate runtime loading check (§3.3's offline diagnostic plus engine entrypoint load) executed against the clone as a confined job. Hive-owned `pkg/` entries may additionally be hashed against the extracted tarball members. Any failure discards the clone and fails the operation before any service signal.
- *Settlement.* A staged candidate is settled when both hold: the job's direct child exited with status 0, and the clone verified. Nothing else is required — not a process census, a guardian, a receipt, or an idle-descendant proof — and the withdrawn `JOB_ACCOUNTING_UNAVAILABLE` refusal must not be reintroduced.
- *Reconciliation.* The operation marker records the job directories, the promotion method, and whether the clone verified. On re-entry after interruption, an unverified `.hive.next` is discarded, leftover job directories are disposed, and a job directory is never adopted as a candidate.

Feasibility evidence gathered 2026-09-14 (macOS 26.6.2, APFS, Node v26.7.0, npm 11.19.0, scratch space only; cite it, do not re-derive it): confinement survived the round-8 escape shape — a writer spawned detached through an intermediate that exited immediately and reparented to launchd got `EPERM` outside the job directory and in `$HOME`, and succeeded inside; the promotion hazard was real — a late write through a descriptor opened before a rename landed in the renamed directory — while an APFS clone taken before that write stayed clean; and a confined `npm install` with lifecycle scripts actually running (pinned `@livekit/rtc-node@0.13.33`, `@livekit/agents-plugin-silero@1.6.4`, `onnxruntime-node@1.24.3`, `@livekit/local-inference@0.2.7`, `protobufjs@7.6.5`, `better-sqlite3@13.0.3`; 193 packages in about 6 s) produced zero permission denials with npm's debug log inside the job cache, after which `onnxruntime-node` and `@livekit/rtc-node` loaded and `better-sqlite3` opened an in-memory database. Not yet proven, and closed by T10 in §8: the pinned Node 24 runtime rather than Node 26; `npm ci --omit=dev` on the real packed artifact rather than a package subset; the SDK's forked job/inference helpers **under confinement** (not merely launched from a confined install — the clone-verification bullet above runs the §3.3 diagnostic and engine entrypoint load as a confined job against the real clone, so that exact step is itself unproven until T10 passes it under real `sandbox-exec` on Node 24); and the deprecation posture above.

Do not delete the only usable prior release before the candidate is healthy. Retain `.hive.broken` for inspection on failed activation, as today. Preserve the existing one-generation rollback semantics after a successful operation; no new release retention system is required. Dry-run describes the target, phases, and recovery capability without fetching, installing, writing files, contacting vendors, controlling services, or sending notifications.

### 5.2 Rollback and compatibility

`hive rollback` restores the previous engine **and** its compatible worker/dependencies together, using the same stop/start order and health checks. No config, Keychain, Mongo data, installed plugins, skills, or agent-authored files are rolled back. This ticket adds no data migration, so reverting code must not require reversing a schema change. If the retained artifact lacks a worker while current config enables LiveKit, reject ordinary rollback before stopping services; do not report an engine-only restoration as voice rollback.

The first migration is exceptional: existing `.hive.prev` may not represent the pilot that launchd actually runs. Preserve a one-time snapshot of the pilot's effective plist/link targets and required non-secret environment settings, plus its exact executable and dependency paths and its actual SDK health listener address/port. Until a previous supported package exists, recovery uses those original definitions and the untouched pilot worktrees, with the pilot-recovery evidence profile in §6. A pilot without the new admission handshake cannot satisfy it through repeated idle polling. Its cutover requires a separately verified maintenance hold covering all dodi dispatch sources and all outstanding dispatch/assignment work; record how that hold is established, checked, and released. If this cannot be established, defer migration or reapply before signaling the pilot and leave operational acceptance pending. Do not retrofit or mutate the protected pilot worktrees to obtain the handshake. Exercise the recovery route during migration, then return to the selected packaged candidate and verify again. Subsequent ordinary rollbacks use `.hive.prev` and require no pilot checkout.

After migration, retain the pilot fallback until a known-good previous supported package supplies independent rollback. The operational record must state which recovery mode is available. Removing a live runtime dependency does not silently discard the only historical recovery route; worktree retirement is outside this ticket and must observe that distinction.

`service/deploy-check.sh` may still serve its existing developer mode, but no existing dodi automation may silently put the pilot or an engine-only release back in service. Inventory and adjust only dodi-specific update entries/pins as part of migration; preserve any shared or Keepur entries. Do not create a new scheduled updater. Existing notification behavior is not an acceptance prerequisite; test/migration commands must honor the execution context's authorization for external notifications.

- **Non-blocking, delegated:** one package with production LiveKit dependencies is the smallest supported extension; its larger installed footprint is accepted for this ticket's design.
- **Non-blocking, delegated:** publish a generated shrinkwrap and use locked production installation; this intentionally stops runtime dependency versions floating independently of a Hive artifact. Future dependency upgrades go through normal package/lock review.
- **Non-blocking, delegated:** an explicit local `.tgz` option shares the supported update path, enabling exact candidate verification without publishing during epic implementation.
- **Non-blocking, delegated:** macOS ARM64/Node 24 is the operational proof target; existing package engine compatibility remains intact.
- **Non-blocking, delegated:** a reversible admission barrier and a 30-second quiescence budget precede planned shutdown; an unresolved/racing call defers rotation with admission restored. This permits a maintenance outage for new calls and promises no active-call migration or zero-downtime release change. Legacy pilot cutover requires the separately verified dispatch hold in §5.2.
- **Non-blocking, delegated:** use the existing SDK health server on an instance-derived loopback port, and existing bridge rejection semantics for no-turn authentication verification.
- **Human decision, binding (May, 2026-09-14):** Seatbelt write confinement, single-use job directories, clone-on-promote, and settlement by direct-child exit plus verified clone replace descendant-process accounting for artifact jobs.
