# KPR-465 — Voice latency: validate warm execution and reduce response pauses

## TL;DR

Turn the September 7 cold-path numbers into a controlled, same-build comparison: measure every stage of a Mokie voice turn on the KPR-464 schema-v2 diagnostics, run the existing post-464 warm lease and at most one further engine-side variable at a time against a cold arm on the same agent/model/voice/script, verify the lease's identity, context, tool, cancellation, cleanup and fallback behavior before it is allowed near a normal call, and let May's blinded per-call verdict on pauses and answer correctness pick the dodi setting. The treatments add no new configuration surface: the shipped warm flag, the KPR-430 static `effort` field delivered on voice turns, and one conditional worker endpointing key. No numeric target and no warm default are chosen here; the specification defines the metrics, the sample plan, the decision procedure, the production-restart rule, the bench clone's containment, and the rollback, and it states plainly that the acceptance cannot complete without May's live-call go on a deployment that carries the KPR-464 instrumentation.

## Key Points

- The comparand is the **in-experiment cold arm on the same build**, measured on schema-v2 denominators (`estimated_eou_to_first_generated_audio`, eligible-only). The September 7 rows and any `scripts/voice-latency-baseline.ts` harvest are historical context only; no blessed W0 artifact exists and none is required.
- Readback of the twelve retained cold "Voice turn complete" rows already answers KPR-323's W1 question: CLI boot-to-init is ~650 ms per turn (≈26 % of first-token p50), model init-to-first-text is the largest term (p50 ≈ 1.3–1.7 s, ≈51–70 %), and queued turns paid 0.8–1.4 s of per-thread lock wait. KPR-323's W1 percentage rule and W2's numeric thresholds are **not selection criteria** for this ticket (§3.4 supersedes them); the lease is still evaluated first because it removes the boot and queue terms and is the only shipped mechanism.
- Voice turns deliver **no `effort`** to the SDK today (the KPR-219 carve-out returns `effortOverride: undefined`; the SDK default is `high` — `sdk.d.ts`: "`'high'` — Deep reasoning (default)"), and the worker runs the SDK's fixed **500 ms minimum endpointing delay** (observed EOU 500–649 ms). These are the two evidence-backed candidate variables after warm. Effort uses the mechanism KPR-430 ⚠ 1 left open — delivering the **static agent-definition `effort` field** on voice turns — and adds no hive.yaml key (KPR-430 §3 names a per-channel value or any hive.yaml knob a non-goal; this spec keeps it so). Endpointing is a config-gated worker lever whose absence is byte-identical to today, built only when the measured decomposition names its stage.
- One variable per arm: cold → warm → warm + static effort (at most two levels, `medium` then conditionally `low`) → (conditional) endpointing. Engine-side terms are measured cheaply on a loopback engine bench against a contained `mokie-bench` clone (`channels: []`, read-only server allowlist, created and deleted inside the bench window); worker-side terms (EOU, bridge hop, TTS TTFB) are pooled from live calls because the engine-side treatments do not touch them. Live calls are reserved for the caller verdict and confirmation.
- Sample plan: the powered claim lives on the bench engine first-text distribution — 36 eligible steady non-tool turns per arm (≈ 8 bench calls of the 10-turn script), derived from the observed ~720 ms standard deviation for a 500 ms minimum detectable median shift and re-derived after the first cold block. The live v2 estimate is confirmatory with its own recorded n (≈ 10 steady turns per arm at two calls) and shortfall; live verdict needs at least two blinded calls per configuration May judges. Numbers here size the experiment; they are not a latency target.
- Warm-path admission to normal calls requires the behavior contract (§5): identity, context, tool ack, barge-in on a live and on an idle lease, idle reclaim, subprocess-kill fallback on both the retry-eligible and the bytes-sent branch, per-exchange duration sanity, and no duplicate or stale speech, proved offline where the SDK is fakeable and on the bench where the real CLI is required.
- Production blast radius is bounded by rule (§6.2): only the warm flag needs an engine kickstart on the dodi instance (effort switches via `admin_agent_update` + SIGUSR1, endpointing via a worker restart); at most two engine kickstarts and one worker restart per session, each only at zero in-flight spawns and zero running worker claims under a quiet-window go, arms ordered as blocks rather than per call. A2's live arm sets Mokie's `effort` for the bench-and-call window only and reverts it (`effort: null`) before the session ends — her non-voice turns share the level for that window, stated and accepted.
- ⚠ Delegated assumptions: a contained clone is an acceptable stand-in for engine-side measurement (Mokie's memory bytes differ; live calls reconcile) and its create/delete each cost one fleet-wide team-summary prefix rewrite; the additive diagnostic fields (`bootToInitMs` on `engine_attempt_terminal`, `queueWaitMs`, `effort`, endpointing) stay within schema v2 with the reader's allowlist extended; delivering the static `effort` field on voice is the "one-line change if wanted" of KPR-430 ⚠ 1, with `effortSource: "static"` unchanged.
- Blocking for execution only: May's explicit live-call go, and a deployed engine + worker that contain KPR-464's instrumentation (the running pilot worker `ab0d2d68` does not — the instance logs hold zero `voice_diagnostic` rows). KPR-466 repeats the chosen configuration end to end.

## 3. Measurement model

### 3.1 Metrics and denominators

Primary comparison metric: the v2 `estimated_eou_to_first_generated_audio` per eligible speech (EOU delay + bound bridge first text + one genuine TTS TTFB, completed non-interrupted `sdk_response` only), read from `voice_diagnostic` JSONL, never from `voice_call_stats` percentiles. It is an estimate, not a handset time; the specification never calls it caller-perceived latency. Openings are excluded (`not_applicable`) and belong to KPR-464/466.

Stage breakdown recorded per turn, each nullable with reason, each attributed to its identity chain (`speechId` ↔ `turnId` ↔ `engineAttemptSeq` through the recorded bindings, never by proximity):

| Acceptance stage | Source field(s) | Owner |
| --- | --- | --- |
| Turn-end detection | `sdk_metric.eou` `eouMs`, `transcriptionMs`, `onUserTurnCompletedMs`; call-level `session_started.endpointingMinDelayMs`/`endpointingMaxDelayMs` (new, §3.2) | worker |
| Lock/queue | cold `lockWaitMs`; warm `queueWaitMs` (new, §3.2) | engine |
| Session initialization | `engine_attempt_terminal.bootToInitMs` (new on the payload, §3.2 — cold every attempt, warm turn 1 only; warm turns 2+ `not_applicable`). Today this stage exists only on the "Voice turn complete" log row (`result.stageTimings.bootToInitMs`), which is not a `voice_diagnostic` field, is emitted on the success path only, and carries `turnId` without `engineAttemptSeq`; that row becomes a cross-check, never the source. | engine |
| First model text | engine `initToFirstTokenMs`, `engine_first_text.firstTextMs`; worker `bridge_first_text.firstTextMs`; delivered `effort` (new, §3.2) | engine / worker |
| First generated audio | `sdk_metric.tts` `ttfbMs`; `synthesis_first_frame` | worker |
| Available playout | `handle_playout_item.startedSpeakingAt`, `output_playback` (call-level, unbound by SDK design) | worker |
| Warm/cold state | `engine_attempt_terminal.warm`, `selectedContinuity`, `launchAdmission`, "Voice turn complete" `warmPath`/`warmTurnSeq` | engine |
| Caller | separately recorded verdict (§6.3); `callerConfirmation` stays `"unknown"` in machine records | human |

Steady turn: an `sdk_response` speech whose engine attempt is not the call's first (`warmTurnSeq ≥ 2` on warm; `selectedContinuity: "resume"` on cold). First turns are reported separately and never mixed into the steady distribution. A turn ≥ 2 that landed through the adapter's outer retry (`engine_attempt_started.continuity: full_transcript`, `selectedContinuity: fresh`) is neither first nor steady: it is the **retried** stratum, reported on its own and never pooled. Turns with `toolCount ≥ 1` are reported as their own stratum because the ack changes what "first text" means (KPR-324). The powered comparison of §3.4 is over steady non-tool turns only.

Percentiles are nearest-rank (`ceil(p·n/100)−1`), reported with n, min, max, and the excluded-by-reason table per arm. A bootstrap 95 % interval for the difference of medians (fixed seed, 2 000 resamples) accompanies every warm-versus-cold claim; a claim of improvement requires the interval to exclude zero **and** the caller verdict of §6.3.

### 3.2 Instrumentation gaps closed (additive, log-only)

- `queueWaitMs` on warm turns: measured from `spawnTurn`'s warm-branch entry to `consumeOneTurn` start, so it folds in both the pending-opening wait (`waitForVoiceOpening`, the V9 case — which sits in `spawnTurn` before `runTurn` and would otherwise be invisible) and the lease's `turnChain` wait; carried on `WarmRunResult`, `stageTimings`, `engine_attempt_terminal`/`engine_terminal`, and the "Voice turn complete" row. Cold turns report `lockWaitMs` unchanged; the comparison reader treats the pair as one "lock/queue" stage.
- `bootToInitMs` on the `EnginePayload` (`engine_attempt_terminal`, mirrored on `engine_terminal` like the other stage measures): cold attempts carry the existing `stageTimings.bootToInitMs`; warm turn 1 carries `openVoiceStreamingSession` call → the `system/init` message observed by `consumeOneTurn`; warm turns 2+ report `not_applicable`; a failed, cancelled or disconnected attempt reports `not_observed`, so the stage has excluded-by-reason accounting like every other. Warm turn-1 `initToFirstTokenMs` is re-based to init → first delta once its `bootToInitMs` exists (today it is push → first delta and would double-count boot); cold `initToFirstTokenMs` is unchanged.
- Delivered `effort` (`low`…`max` or `null`) on `engine_attempt_terminal` — the value the envelope actually carried, so an undeliverable static field (haiku tier, off-catalog) reads `null` — and the effective endpointing (`endpointingMinDelayMs`, `endpointingMaxDelayMs`, `turnDetection`) on `session_started`. Numbers and enum strings only.
- These are optional keys under `schemaVersion: 2`; `parseVoiceDiagnosticEvent`'s allowlist is extended in the same change, KPR-464-era rows without the keys still parse, and the checked-in fixtures cover both shapes. ⚠ If review prefers a version bump, the reader must accept v2 and v3 and the comparison mode must refuse to pool arms across versions.
- Privacy posture unchanged: no transcript, phone number, tool argument, ack text, or prompt bytes in any new field.

### 3.3 Comparison reader

Extend `scripts/read-voice-diagnostics.ts` (or add `scripts/voice-latency-compare.ts` sharing `voice-diagnostic-reader.ts`) with a multi-call comparison mode: input one or more bounded JSONL files (reuse `MAX_VOICE_DIAGNOSTIC_BYTES`), a call-id allowlist with an explicit arm label per call, and an optional engine-log path for the retained "Voice turn complete" rows used only as a cross-check (per-`turnId` agreement of `bootToInitMs`/`initToFirstTokenMs` with the JSONL, reported as a mismatch count; every stage distribution comes from `voice_diagnostic` rows). Output per arm and per stratum (steady/first/retried/tool): the primary estimate distribution, each stage distribution from §3.1, excluded-by-reason counts, incomplete/unbound counts, warm-state consistency checks (an arm labelled warm whose steady turns are not `warm: true` fails the run; an arm labelled cold containing any `warm: true` steady turn fails the run), and the median-difference intervals. Engine-only inputs (bench calls, §4.2) produce engine-stage distributions and an explicitly labelled "bench-composed estimate" = pooled live EOU p50 + engine first text + pooled live TTS TTFB p50, which is never presented as the v2 in-call estimate. No Mongo, no config, no network, deterministic output for the fixtures.

### 3.4 Sample plan and target-selection procedure

Sample size before claiming improvement: the ten September 7 cold first-token values have standard deviation ≈ 720 ms, and that is an **engine first-text** figure — so the powered claim is carried by the engine first-text stage, not by the composite. For a minimum detectable median shift of 500 ms at α = 0.05 (two-sided) and 80 % power, a two-arm comparison needs ≈ 33 turns per arm by the t approximation, ≈ 34 with the Mann-Whitney efficiency correction; the plan uses **36 eligible steady non-tool turns per arm** as the default. Which distribution carries which claim:

- **Powered (bench, Tier E):** engine `initToFirstTokenMs` on steady non-tool turns, and the bench-composed estimate derived from it (§3.3). The §6.1 script yields about five such turns per call (ten turns minus the first turn, the two barge-in turns excluded as `interrupted`, the tool turn stratified out, and the goodbye), so 36 per arm means **≥ 8 bench calls per arm**; bench calls are cheap and the count is not a constraint. After the first cold bench block the standard deviation is re-estimated from that block and the per-arm minimum is re-derived and recorded before any treatment arm is analysed.
- **Confirmatory (live, Tier L):** the v2 in-call estimate and the worker stages, at the live n actually collected (≈ 10 steady non-tool turns per arm at the §4.2 minimum of two calls). Its interval is reported with its own n and an explicit shortfall against 36; it confirms or contradicts the bench direction and is never presented as the powered claim. If a live block contradicts the bench direction, the contradiction is recorded and the arm is not a candidate until it is resolved by more live calls under a fresh go.

A shortfall on either tier is reported as a shortfall, never rounded up to a claim. The 500 ms figure sizes detectability; it is not a target.

KPR-323's numeric rules are superseded here: its W1 falsification percentage (the "< 40 % of first-token p50" rule, which §2 notes the lease alone fails at ≈ 26 %) and W2's `[baseline − 800 ms]` / `≤ 900 ms` thresholds are **not** selection or demotion criteria for this ticket and are not to be imported into the evidence record as a bar. Under this epic's canon no numeric bar exists until May sets one; the only demotion paths are a §5 contract failure and the quality gate below.

Target selection (procedure only; no number chosen by this specification): (1) collect the arm distributions per §3.1; (2) collect May's blinded per-call verdicts and per-turn correctness records per §6.3; (3) an arm is a candidate only if it passes the §5 behavior contract **and** shows no correctness regression against the cold arm on the scripted expected answers (§6.1) — a quality regression disqualifies the arm regardless of its latency; among candidates, the configuration with the best pause verdict is chosen; if May judges none acceptable, the current cold configuration stays and the gap is recorded; (4) the recorded target for KPR-466 is the candidate arm's measured steady p50 and p95 of the primary estimate, or an explicit number May states after hearing the calls — whichever she chooses — written to the epic decision register with its provenance. A machine improvement that May does not hear as an improvement does not become the target.

### 4.1 Levers

Static `effort` on voice (engine) — **mechanism chosen: (a), the KPR-430-sanctioned change; no new hive.yaml key.** KPR-430 ⚠ 1 excluded voice from the static field's delivery ("one-line change if wanted"), and KPR-430 §3 lists "per-channel effort (e.g. a separate voice value), `thinking` config, or any `hive.yaml` knob" as non-goals. Round 1 of this spec proposed a `voice.effort` key under the wrong precedent; a per-channel key is the mechanism KPR-430 declined, and it would also be a preemptive lever the operator's standing posture rejects. The change is therefore: the `prepareSpawn` voice carve-out calls the existing `resolveStaticClaudeEffort(agentConfig, staticTier, agentId)` and returns its result as `effortOverride` with the existing `effortSource: "static"` (no `EffortSource` union change); `openWarmLease` passes the same resolved value into `openVoiceStreamingSession` (new optional `effort` param forwarded to `buildQueryEnvelope`, which already delivers `effort`), so a lease pins it for the call like the model and prompt. Delivery reuses KPR-430's gate (`supportsEffort(model)` and tier ≠ haiku, warn-once otherwise). Lane A/B, reflection and worker turns are unchanged; the delivered value is stamped on `engine_attempt_terminal` (§3.2) and on `agent_turn_telemetry.effort` through the existing KPR-430 stamp site (which voice turns reach for the first time). Absence of the field on the definition leaves every voice turn byte-identical to today. Canon R3's "tool-ack, KPR-399/434 predicates unchanged" is preserved. Cost of this choice, stated: the field is agent-wide, so during an A2 live window Mokie's non-voice turns run at the same level (§6.2 bounds the window and mandates the revert); the bench clone carries the field freely. KPR-430's ⚠ 1 rationale ("a `max` on a realtime voice turn is a latency footgun") is honored by the A2 level cap — `xhigh`/`max` are never delivered in this experiment, and a definition carrying them would deliver them on voice after this change, which the evidence record and `docs/providers.md` must say.

`voice.livekit.endpointing.{minDelayMs,maxDelayMs}` (worker): optional integers validated (`0 ≤ min ≤ max ≤ 10000`), passed as `turnHandling.endpointing` in `session.ts`; absent → SDK defaults, byte-identical session options. Stamped on `session_started`. Interruption, preemptive and false-interruption options are not exposed.

Neither lever changes a default. Both are experiment instruments; a selected value, if any, lands only through §6.4 — the warm flag and endpointing as dodi `hive.yaml` keys, the effort level as Mokie's definition field.

### 4.2 Evidence tiers

- **Tier E — engine bench (no PSTN, no vendors, no May).** `scripts/voice-engine-bench.ts`, operator-run on the instance host: resolves the bridge token the way the worker does (`resolveSecretEnv`, never logged), posts the fixed script (§6.1) turn by turn to the loopback `/v1/chat/completions` with the worker's exact request shape (`call.metadata.hive_agent_id`, `goal`, `context`, `metadata.voiceTrace` with a bench `workerBootId`), streams SSE, and writes a small result file (call id, arm, turn, client-observed first-text ms, text length). Engine stages come from the engine's own `voice_diagnostic` rows for those call ids. Supports: sequential calls (≥ 8 per arm, §3.4), a barge-in step (close the response mid-stream), a rapid double-request at call start, three concurrent bench calls, a mid-call CLI-subprocess kill drill on each V6 branch, and a per-turn assertion record (expected-answer match on the factual turns via a fixed keyword check, `toolCount ≥ 1` on the lookup turn). Runs against a contained `mokie-bench` clone, never against Mokie (KPR-323 W2's "test agent — never production defs" rule for engine-side work; live calls must use real Mokie because the verdict is about her, §4.2 Tier L). The clone's definition:
  - `_id: mokie-bench`, `roles: ["Bench stand-in (KPR-465) — do not message"]`, `disabled: false` (a disabled definition is diverted to `disabledAgents` at load and is not spawnable), same `model`, `soul`, `systemPrompt`, `timeoutMs`, `spawnBudget: 5`, `effort` per arm (absent on A0/A1).
  - `channels: []`, `passiveChannels: []`, no `schedule`, `delegateServers: []` (voice resolves the agent by `call.metadata.hive_agent_id` through `registry.get()`, so no channel is needed).
  - `coreServers` is an **allowlist of read-only, in-process servers only**: `memory`, `structured-memory`, `contacts`, `conversation-search`, plus any read-only search server Mokie carries. Everything in `WORKER_SERVER_DENYLIST` (slack, quo, resend, team, event-bus, callback, schedule, recall, voice, voice-livekit, admin, worker-pool, background, keychain, code-task) and every vendor write surface (google, linear, github-issues, clickup, tasks, browser, brave-search) is excluded; the clone can place no call, send no message, and write nothing but its own memory. The auto-injected `team`/`schedule`/`team-roster` servers remain (it is an ordinary runner, not `suppressAutoInjectedServers`); the `team` surface is what the `roles` label and the delete window bound, and the bench evidence lists any `team_messages` row naming the clone (expected: none).
  - The §6.1 lookup turn therefore targets a read-only tool the clone and Mokie both carry (`contacts` lookup, or a `conversation-search` query), so V3 exercises the same tool on both tiers.

## 6. Live execution protocol

### 6.1 Script

One fixed 10-turn caller script per call, identical across arms: quiet answer (KPR-464 L1 shape), three short factual exchanges, one turn that references an earlier answer (V2), one turn that forces a lookup through a read-only tool both Mokie and the clone carry (V3, §4.2), two marked barge-in points (V4 — one mid-sentence, one during a tool wait), one deliberately long question, and a normal goodbye with hangup. The caller lines are fixed strings checked into the bench script; they contain no personal data. Every non-barge-in turn carries a **fixed expected answer** checked in beside its line: for the three factual exchanges and the long question, a short keyword set the answer must contain (facts the agent can answer without tools, so correctness is not vendor-dependent); for the recall turn, the fact from the earlier answer it must repeat; for the lookup turn, the expected lookup result and the requirement that the tool was actually called (`toolCount ≥ 1`). Repeats and failed calls are recorded, never excluded.

### 6.2 Preconditions and stop rule

Every live call requires: May's explicit go for that session; a KPR-463-supported deployment whose running engine and worker identities are read back and recorded together with `@livekit/agents` 1.6.4, the flag values of the arm, Mokie's model and voice id, and the UTC clock basis; and the §5 offline rows green on that build. On identity or config drift, an unexpected destination, lost correlation, or May's stop request: stop dialing, hang up, keep the attempt in the denominator as failed/incomplete, and do not retry under the same go.

**Production restart rule (blast radius).** `voice.warmPath.enabled` and `voice.livekit.endpointing.*` are boot-time reads (SIGUSR1 reloads agent definitions, not `hive.yaml`), so switching them means an engine kickstart or a worker restart on the **production dodi instance** — a kickstart kills every in-flight dodi turn across all agents and channels and cold-starts the prefix and API caches. The rule, binding for bench and live sessions alike:

- Only the warm flag and the endpointing key restart anything. The effort arm switches through `admin_agent_update` + SIGUSR1 (no restart), and every arm's runtime state (flag values, `effort`, endpointing) is read back and recorded before the first call of the arm.
- Arms are run as **blocks**, not interleaved per call: one cold block and one warm block (A2's levels sit inside the warm block, switched by definition edit), so a session needs at most two engine kickstarts (into the warm block and back to cold at session end — or one, if the session ends warm under a go that says so). A3, when built, adds at most one worker restart pair in its own session. **Cap: two engine kickstarts and one worker restart per session**; a session that would need more stops and continues under a new go. Which block goes first is randomized per session and recorded — that is what "randomized order" means in this spec.
- A kickstart or worker restart is issued only inside a declared quiet window covered by May's go for the session, and only after a quiescence check immediately before it: the freshest `spawn_coordinator_stats` heartbeat (≤ 30 s old) shows `activeSpawns == 0` and `warmVoiceSessions == 0` for every agent, `meeting_worker_claims` has no `status: "running"` document (pool spawns are outside `getSnapshot()`), and no live call is up. The check and the restart timestamps are written to the evidence record; a turn that starts inside the ≤ 30 s heartbeat window is the accepted residual, and the bench script's first turn after every restart is a discarded warm-up.
- The A2 live window: Mokie's `effort` is set immediately before the first A2 live call and reverted (`effort: null` + SIGUSR1) immediately after the last, inside the same quiet window; Mokie's non-voice turns during that window run at the fixed level and are listed (by count, from `agent_turn_telemetry.effortSource: "static"`) in the evidence record. A session may not end with the field set.
- Running Tier E on a separately booted engine process was considered and rejected: it would need its own instance config and datastore and would not measure the dodi engine's in-process state; the bench therefore runs on the dodi engine under the same rule, in the same quiet windows as the clone's create/delete (§4.2).

### 6.3 Caller verdict

After each call, before being told the arm, May records: pauses (acceptable / borderline / annoying), whether any response felt cut off or Mokie talked over her, whether interruptions behaved naturally, whether anything replayed or sounded stale, a **per-turn correctness mark** for each scripted turn that carries an expected answer (§6.1: correct / wrong / missing, from her own ear during the call — the recall turn and the lookup turn included), and free text. The record stores the verdict against the call id with the time of the observation; it is human evidence and never populated from machine timestamps. Her free text is stored verbatim only with her ok; otherwise it is paraphrased and marked so. Machine measures, the bench-side correctness assertions and the verdict are presented side by side in the evidence record; disagreement is reported, not reconciled away.

### 6.4 Choosing the dodi setting and rollback

The candidate configuration from §3.4 is applied to dodi only as `hive.yaml` keys (`voice.warmPath.enabled`, optionally `voice.livekit.endpointing.*`) through the supported deployment path plus, if an effort level was selected, Mokie's definition `effort` field via `admin_agent_update` + SIGUSR1, with the decision, the numbers, the verdict, and the rollback written to the epic decision register. Rollback is key removal plus the corresponding service restart for the two `hive.yaml` levers and `effort: null` + SIGUSR1 for the field; the engine default remains off for the two keys and the field is absent by default, so a fresh install or a lost `hive.yaml` edit is cold by construction. If no arm passes §5 or earns an acceptable verdict, the recorded decision is "keep cold" with the measured gap, and KPR-466 proceeds on cold.
