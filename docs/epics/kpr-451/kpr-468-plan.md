# KPR-468 notifier implementation plan

> **For agentic workers:** Execute this plan through the epic implementation lane (`dodi-dev:implement-ticket`). Read this index and all nine chunk files as one plan before starting Task 1. **KPR-454 must be merged first** — see "Ordering dependency" below; this plan is unimplementable before it lands.

**Goal:** Own `ops_notifications` — the KPR-458 D7 acknowledgement ledger — and the bounded 30 s sweep that mints and renews rows from the `matchedSubscriptionIds` KPR-454 stamped, delivers each through an `OpsTransport` adapter, nudges on an operator-registered cadence, expires snoozes, applies clearing facts, and accepts one attributed acknowledgement act at a time through a bounded, idempotent, attribute-or-refuse intake. Hold no policy: re-evaluate no filter, author no cadence, resolve no recipient, ship zero rows of KPR-458 D11's third column.

**Architecture:** One `OpsNotifier` runtime on the `src/obligations/runtime.ts` shape (`init()` / `start(...)` / `stop()`, a live transport bound at `start()`, a bounded non-overlapping sweeper). Its durable state is two new collections — `ops_notifications` (the ledger, nine indexes) and `ops_policy` (one operator-written document, **zero rows ship**) — plus one `db.telemetry` cursor document (`kind: "ops_sweep_cursor"`) and one heartbeat document (`kind: "ops_notifier_stats"`). Each 30 s tick runs three contained phases in a fixed order — **ingest** (event-level containment, apply-if-strictly-newer CAS over `(publishedAt, _id)`), **snooze expiry**, then **delivery** (three index-separated scan arms, per-row containment) — checks its stopped latch between rows, between events and between phases, and closes with the heartbeat, which is written even when a phase read throws (`state: "degraded"`). Acknowledgement intake is the one non-swept path: a direct, deadline-bounded read-plus-CAS on the acknowledging caller's own thread, live from `init()`, serialized against the tick by a per-row in-process latch. One transport ships: `SlackOpsTransport`, a separate class from KPR-456's `SlackObligationPoster` that copies its hardening item for item and registers every accepted `ts` through `SlackGateway.registerOutboundTs`.

**Tech Stack:** Existing TypeScript strict / Node 22–24, MongoDB driver 7, `@slack/web-api` (already a dependency, KPR-456's client), Vitest. No dependency addition. No `hive.yaml` key.

**Approved input:** [KPR-468 design](kpr-468-design.md), clean at spec-review round 5 plus post-approval advisories, commit `b8c923b` on `epic/kpr-451`. Contract: [KPR-458 design](kpr-458-design.md) D2/D3/D4/D5/D6/D7/D8/D9/D10/D11/D12 and C1–C19, with C8/C9/C10/C14/C17 the criteria this child is measured against. Producer: [KPR-454 design](kpr-454-design.md) and its plan ([index](kpr-454-plan.md) + chunks [1](kpr-454-plan-1-prefix-table.md), [2](kpr-454-plan-2-contract.md), [2b](kpr-454-plan-2b-contract-tests.md), [3](kpr-454-plan-3-publisher.md), [4](kpr-454-plan-4-capture-and-boot.md), [5](kpr-454-plan-5-acceptance.md)).

**Epic Decision Register canon** (read live from KPR-451 at plan time — sixteen lines, KPR-453 ×4, KPR-456 ×6, KPR-457 ×6). All sixteen are preserved and none is amended. The four that bind hardest: KPR-456's "no default recipient, severity, escalation, production registration, prompt rollout, or new policy dependency is supplied" (this ticket registers **zero** `ops_subscriptions` rows, **zero** `ops_policy` rows, and no `hive.yaml` key); KPR-456's "ambiguous deliverable/notice submissions remain unknown without automatic resend; only the closed provenance-checked nonacceptance allowlist permits retry … This obligation-specific contract does not supersede Beekeeper's separate alert retry contract" (this child ships **no retry ladder**, and `SlackObligationPoster` is neither reused nor refactored); KPR-457's "this separate contract does not supersede KPR-456's unknown/no-automatic-resend rule" (three separate contracts, three separate classes); and KPR-453's "identity proves neither unique attempt nor task continuity" (the `evidence` references rendered into a `NotificationView` are references a responder opens, never a join key — the notifier stores no work-item identity of its own).

## Test-double decision

**Extend KPR-454's `src/ops/testing/fake-db.ts`; do not add a second double.** The deciding argument is ownership, not convenience: the file the spec warns about touching is `src/obligations/testing/fake-db.ts`, a **KPR-456** test surface, and an edit there is genuinely cross-child. `src/ops/testing/fake-db.ts` is a file **this epic creates one child earlier, in the same module directory**, so extending it is an intra-epic additive edit of exactly the kind KPR-454's own plan already performs against the obligations original (it copies four capabilities and diverges deliberately on two). A second double in `src/ops/` would mean two harnesses for one collection family and two places for a filter-engine bug to hide.

KPR-454's double already provides what integration point 9 names as mandatory: **real `ObjectId` minting** (its plan's fourth harness bullet, a deliberate divergence from the obligations original's counter strings, which invert lexicographically at n ≥ 10), a `sort`-honouring `findOne`, `find().sort().limit()`, `pause`, an `operations` log, `countDocuments`, and programmable per-operation faults. Six things it does not, each additive:

1. **`countDocuments` must honour `options.limit`.** The obligations original returns `…filter(...).length` and never consults a limit (`src/obligations/testing/fake-db.ts:271-278`), while `find()`'s cursor does (`:266`, `.slice(0, limit)`); KPR-454's plan copies that method verbatim ("copy, do not invent"). Every saturation assertion in this ticket — `eventsBehind` and the four gauges — is unfalsifiable without the fix, and a test written against the unfixed double would pass while asserting nothing. **One line**, and it makes five assertions real.
2. **`updateOne` must reject an update naming one path in both `$set` and `$unset`.** The original applies `$set` (`:293`) then `$unset` (`:294`), silently resolving a conflict real MongoDB rejects ("Updating the path 'stalledAt' would create a conflict at 'stalledAt'"). This is the highest-value harness addition in the plan: the write that would trip it is the delivery phase's **no-interval branch**, i.e. the shipped-default path, the most common write there is (D5 step 5). Against the unfixed double the buggy build goes green and throws in production on the first tick.
3. **Unique-index enforcement on `insertOne`.** D4's write is a conditional-update-then-insert whose second step depends on the duplicate-key error _being_ the race detector (`renewalStale`). The obligations original enforces unique indexes (`unique(row, oldId)`); KPR-454's harness requirement list does not promise it, so this plan re-states it as a requirement and Task 3 Step 2 verifies it before relying on it.
4. **Comparison operands that are `ObjectId`s must be coerced with `String(...)`.** The original's `$lt`/`$lte`/`$gt`/`$gte` compare raw (`:38-45`). **This ticket sidesteps the hazard rather than depending on the fix** — every event reference the ledger stores (`appliedThroughId`, `firstEventId`, `latestEventId`, `stateEventId`) is a **24-character lowercase hex string**, whose lexicographic order is byte-identical to `ObjectId` order and which KPR-454's own resolver already treats as the canonical total order (`String(a._id)`). The coercion is still added, because the ingest page filter compares `_id` on `ops_events` documents directly.

5. **`copy` must preserve `ObjectId`.** The head-of-file `copy` is bare `structuredClone` (`src/obligations/testing/fake-db.ts:6`) and `operation()` returns `copy(action())` (`:89`) and `copy(result)` (`:96`), so every document the double **hands back** carries an `_id` degraded to `{ buffer }` — `instanceof ObjectId` false, `String(...)` `"[object Object]"` (measured). Filtering is unaffected (`matchesFilter` runs over the un-copied rows), which is what makes this invisible to a grep for minting; what it breaks is `String(e._id)`, i.e. every event reference the ledger stores and the sweep cursor itself. **Also filed against KPR-454**, whose own `(publishedAt, _id)` tie-break case has the identical exposure; if that child lands the preserving clone first, Task 3 Step 2(f) is a no-op to verify.
6. **A PERSISTENT fault and a fault reset — `failAlways` / `clearFaults`.** The original's `failNext` pushes a **one-shot** hook that is spliced out when it fires (`src/obligations/testing/fake-db.ts:98-105`), so the same operation cannot be made to fault on two successive ticks. AC13's third ingest limb — the only case that pins D8(b)'s "no automatic skip and no quarantine" **ruling** rather than restating it — needs exactly that: against a bounded-quarantine implementation, a one-shot fault lets tick 2 succeed and the limb passes. This is the one genuinely new capability the ticket needs from the double.

**The fault-injection spellings this plan needs and does NOT add.** `failNext(collection, operation, after = false, when = () => true)` already takes a **predicate**, evaluated once per matching call, and the hook stays armed until it returns true. So the "nth call" fault is `let seen = 0; failNext(c, o, false, () => ++seen === n)` and the "call matching a predicate" fault is `failNext(c, o, false, when)`. Both are one-line helpers in the harness module (`failNth`, `failOn`), not double API — recorded here because a step whose diff is unknown at review time is not reviewable, and round 1's escape hatch ("use whatever the file exports, or add something and say so") was exactly that.

**Assertions that are unfalsifiable against any double, named so nobody writes one and believes it.** The double models neither index selection nor index options, so **every index-_property_ claim in D2 and D5** — arm 2's and the four gauges' leading-key bounds, "`state` is in the index rather than a residual filter over it", "no index here is `sparse`" — is checked by asserting the **exact `createIndex` specs that were requested** (chunk 2 Task 3 Step 4 reads the fake collection's `indexes` array), which pins the shape and says nothing about a planner. Only a live-Mongo test could confirm use, and none ships. Likewise the TTL: assert `{ expiresAt: 1 }` with `expireAfterSeconds: 0` was created and that `expiresAt` is set and unset exactly per D9's state invariant — never that a row disappeared. Likewise write concern: assert the `{ w: "majority", wtimeoutMS: 5000 }` option was passed, never that it was honoured. **AC7's starvation case is unaffected and is correctly shaped** — it asserts a behavioural outcome (a freshly-minted row is delivered on a tick where a large stall backlog is already due), which is false of a single-scan implementation regardless of what any double does with indexes.

## Numeric bounds resolved at plan time

The spec (Assumptions, `⚠ Delegated`) fixes the behaviour on breach and leaves the values here. All live as named `const`s in `src/ops/notification-types.ts`; **no `hive.yaml` key ships for any of them** (standing "no preemptive levers" preference), so each is a code change. The last four rows are values the spec itself fixes and are restated so the implementer has one table.

| Constant                 | Value                                    | Reasoning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------ | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `INGEST_PAGE_SIZE`       | `200`                                    | One event costs at most one indexed `find` on the clearing arm plus, **per stamped subscription, up to three round trips** — `applyRenewal` tries the reopen arm, then the advance arm, then an insert, and the create path pays all three. Under the shipped default (zero subscriptions) that is one read and nothing else; under a loaded deployment at ≤5 subscribers per event a 200-event page is **≤3000 round trips**, not the ≤1000 an earlier draft of this row claimed — still seconds at worst against a local `mongod`, inside a 30 s tick with two phases to run, and the steady state is the cheap one (an existing row resolves on arm A or B; three trips is the mint-only cost). If that ceiling ever binds the lever is this number, not a fourth write arm. |
| `INGEST_EVENT_BUDGET`    | `1000`                                   | Five pages per tick ⇒ ~33 events/s of sustained drain, which is >100× the publish rate KPR-454's own evidence measured (a week of live traffic produced hundreds of tool failures, not thousands per minute). Breach defers to the next tick and is visible as `eventsBehind`; nothing is dropped and nothing is skipped (D3).                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `EXPIRY_PAGE_SIZE`       | `200`                                    | The expiry phase is one bounded indexed scan and one CAS per row, with no transport call in it; 200 is the same order as the ingest page and cannot on its own consume the tick. A larger expiring cohort defers to the next tick, which costs it one 30 s interval — acceptable for a pause the acknowledger themselves set.                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `DELIVERY_BUDGET_MS`     | `10_000`                                 | A third of the 30 s interval, leaving room for ingest, expiry and the heartbeat. Combined with the spacing below the honest bound is **~10 attempts per tick (~20/min)**; a larger due cohort defers and is visible as backlog, which is the right trade under the shipped default where each row is attempted once per occurrence. The budget is checked **between rows** and **before** both the spacing sleep and the adapter call, so worst-case phase duration is `DELIVERY_BUDGET_MS + ATTEMPT_SPACING_MS + SLACK_POST_TIMEOUT_MS` = **21 s** < 30 s — a tick cannot run into its successor. (An earlier draft said 20 s by omitting the spacing; the conclusion is unchanged and the arithmetic now matches the code.) Even if it did overrun, `sweepOnce()`'s single in-flight promise means the next interval tick is a no-op rather than an overlap — KPR-456's `sweeper.ts:106-117` precedent. |
| `DELIVERY_ARM_PAGE_SIZE` | `200`                                    | Bounds the **read** per delivery arm. **One implementation choice the spec explicitly leaves open, taken here to remove a branch.** D5 says `oldestUnappliedAt` is free when the tick's budget trips _inside_ a page and costs one extra bounded indexed `findOne` on a page-boundary or contained-fault stop, and that the implementer may instead define the stop to always leave a page in hand. **This plan takes neither of the two-branch forms: the ingest loop checks its budget _between_ pages and every non-drained stop performs the one extra `findOne`.** One mechanism, always, no branch to get wrong, and the read is on the same `{ publishedAt: 1, _id: 1 }` index the page sort already uses. The fault-stop branch's one-directional property is preserved and must be stated in the code comment: because D8(b) permits a mid-page fault to leave the cursor **where the tick found it**, the read can return an event that has already been applied, so `oldestUnappliedAt` is an **upper bound** on the true age — which errs toward alarm, the safe direction for the one gap this figure exists to expose. What is fixed regardless: `oldestUnappliedAt` is **always reported** and never silently omitted.

**One ambiguity the spec leaves and this plan closes, because the obvious reading is wrong.** D5's snooze expiry sets `delivered` "if the row has a recorded `accepted` outcome, else `pending`". The `attempts[]` ring is capped at 5, so a row nudged six times since its accepted delivery no longer _records_ that outcome in the ring, and a ring-derived test would demote it to `pending`. The durable marker is **`deliveryReference`**, which is written only on an `accepted` outcome and is never unset — so the expiry arm tests `row.deliveryReference !== undefined`. Stated here because an implementer reading D5 literally will reach for the ring.

### Critical Flows

- Event stamped `[s1]` → ingest applies it → one `pending` row for `s1` with `nextNudgeAt = now`, `attemptCount: 0`, `appliedThrough*` at the event's `(publishedAt, _id)` — and **no** row for an enabled `s2` whose filter would also have matched.
- Same event re-read after a simulated crash between the last ledger write and the cursor advance → total no-op; a page holding two events for one `dedupeKey` replayed leaves `eventCount` at **2**.
- Ingest fault on the third event of a five-event page → the phase stops at it, the cursor sits at or before the second event's position, and the next tick applies 3, 4 and 5. A deterministic fault on the same event across two ticks leaves `cursorAt` byte-identical, `ingestFaults` at 2 and the heartbeat `degraded`.
- Clearing event with **zero** `matchedSubscriptionIds` → every row on the named `dedupeKey` clears, across all subscriptions. A clearing event from producer `B` naming a `dedupeKey` under producer `A` clears nothing and counts `clearRefused`.
- Fresh row under **no** `ops_policy` → attempted once (arm 1), `accepted` ⇒ `delivered`, `nextNudgeAt` pushed to `now + STALL_RECHECK_MS ± jitter` with `stalledReason: "cadence"`, and never nudged again until its next occurrence.
- Cleared row renewed under no `ops_policy` → reopened `pending` with `forceDeliver: true` → **delivered again** on the next tick through arm 2, `attemptCount` now 2.
- Snoozed row whose `snoozedUntil` elapses → expiry (running **before** delivery in the same tick) returns it to `delivered`/`pending` with `forceDeliver: true` and `nextNudgeAt = now` → delivered on that same tick.
- A stall backlog larger than the delivery budget, all due, plus one freshly-minted row → the fresh row is delivered **on that tick**.
- `accept({ act: "seen", at: t1 })`, then `accept({ act: "snoozed", at: t2 > t1 })`, then a replay of the `seen` → `{ state: "noop", reason: "superseded" }` with the row's `snoozedUntil` and `expiresAt` byte-identical.
- `accept(...)` with `at = now + 10 years` on an `integrity` row → applied with `snoozedUntil ≤ now + HARD_SNOOZE_CEILING_MS` and `stateAt ≈ now`; a following honest act by the same actor is not superseded.
- `accept({ actorId: OPS_SYSTEM_PRINCIPAL })` → `refused: "unattributed"`, row byte-identical.
- Accepted Slack post → `registerOutboundTs(channel, ts)` called with the returned pair; `deliveryReference` is `{ kind: "slackMessage", id: "<channel>:<ts>" }` and no URL is stored.
- A storage fault on a read that sits outside every inner `try` — the cursor read, the ingest page `find`, a gauge `countDocuments` — leaves the tick **resolved, not rejected**, counts `sweepFaults`, and still writes a `state: "degraded"` heartbeat. (Without the containment frame in `OpsNotifier.run()` the throw reaches `sweepOnce`'s `.catch`, which counts and writes **nothing**, and the wedge signal KPR-455 reads goes silent on exactly the fault class an operator most needs.)
- `stop()` mid-tick: ingest exits between events, expiry and delivery never start, and the drain waits for one event's application rather than a whole `INGEST_EVENT_BUDGET`.
- Boot: unique-index failure ⇒ notifier unstarted **with the singleton unset**, `accept(...)` returns `unavailable`, boot completes. Reason-map failure ⇒ singleton **set**, sweep off, `accept(...)` on an existing row **applies**. First-subscription-load failure in `start()` ⇒ unstarted with intake live.
- Shutdown: `stop()` before Slack and Mongo close; the in-flight tick exits at its next inter-row checkpoint.

  **NV7 — the intake monotonicity guard and its anchor** (chunk 6 Step 9, AC8; rehearsed in chunk 4 Step 6). TWO mutations, ONE point, run in sequence. Delete the `lastAckAt` precondition from step 3 and from the step-8 CAS. Fails `AC8 › a delayed duplicate of an older act is superseded, not applied` — the replayed `seen` applies, the row leaves `snoozed`, and `snoozedUntil` is unset. Predict that `AC8 › a duplicated dismissal returns noop/already-applied` **stays green** (`lastAckKey` alone carries it), which is exactly why the monotonicity case is written separately. Then the paired anchor mutation: guard on `principalAt` instead of `lastAckAt`. Predict the **inverse** pair — the delayed-duplicate case goes green again, and `AC8 › a system transition between a human act and its callback does not supersede that callback` fails, with the callback returning `superseded` and a real act lost.
  **NV8 — boot order** (chunk 5 Task 7 Step 7, AC14). Relocate the whole `opsNotifier` wiring block from above the boundary marker to **immediately after `await bgTaskManager.scanOrphans();`**. Fails **both** `(b)` and `(c)`; `(a)` is presence-only and stays green, and so does the new `(d)` — it bounds `start()` against the wiring, and the relocated wiring still precedes `start()`. ## Assumptions carried into implementation

Each is one line; all are non-blocking and all are the spec's own unless marked, restated here so the implementer does not re-derive them.

- Idempotence is **apply-if-strictly-newer** over `(publishedAt, _id)` on every ledger application, a strengthening of D12's `latestEventId`-equality phrasing within the contract's own stated intent — and KPR-458's pending Task-2 addendum owes one line recording that (spec Assumptions; **this plan does not execute the recording**, it carries the obligation forward).
- The D12 sweep cursor is one `db.telemetry` document, `kind: "ops_sweep_cursor"`, beside but never merged with the `ops_notifier_stats` heartbeat.
- A missing cursor initializes to the **server clock**, never to the beginning of the log; no backfill, counted `cursorReinitialized`.
- `ops_policy` is a new collection, one document `_id: "ops"`, read once per tick and **retained**; zero rows ship.
- No cadence registered ⇒ a row is **attempted once per occurrence** (delivered if the transport accepts) and never nudged between occurrences; its realization is the stall-forward plus the three-arm split plus the three-disjunct attempt gate, all fixed in D5.
- A sparse `forceDeliver: true` is written at exactly two arms (the `cleared → pending` reopen and snooze expiry), cleared by the attempt that consumes it and by an intake `seen`/`dismissed`, and never cleared by a skip.
- Every clock-bearing intake write is anchored at `anchorAt = min(at, now)`; `lastAckKey` alone keeps the raw `at`.
- No retry ladder ships: `rejected` is recorded and the row's next attempt is its next ordinary nudge (D6 supplies no retry hint to schedule from).
- The `judgment` / `integrity` clearing provenance test requires same-producer **and** at least one `evidence` reference.
- Ledger TTL is `min(30 days, config.activity.retentionDays)` and is the acknowledgement-silence horizon, not only a privacy setting.
- A contract-side `HARD_SNOOZE_CEILING_MS` of 7 days exists in code so a clamp always exists; a registered maximum can only tighten it.
- Exactly one transport ships and it is Slack; `SlackObligationPoster` is neither reused nor refactored.
- Intake idempotence keys on `(row, act, actorId, at)`, paired with a `lastAckAt` monotonicity guard.
- The acknowledgement handle is the row `_id`'s hex string and confers no authority — attribution, not authorization.
- **Plan-writer's own, stated in full above:** every event reference stored on a ledger row (`appliedThroughId`, `firstEventId`, `latestEventId`, `stateEventId`) is a 24-character lowercase hex string rather than an `ObjectId`, because hex order is byte-identical to `ObjectId` order and KPR-454's resolver already treats `String(_id)` as the canonical total order — which removes the double's raw-comparison hazard from the ledger entirely.
- **Plan-writer's own:** snooze expiry decides `delivered` vs `pending` from `deliveryReference !== undefined`, not from the `attempts[]` ring, which the cap can drop.
- **Plan-writer's own DEVIATION, stated against the sentence it departs from.** D4 says a clearing fact applied to an already-`cleared` row is a no-op "**by the D3 watermark**". The watermark alone is not sufficient for that: it stops an OLD or REPLAYED clearing event, but a **genuinely newer** one re-applies, advancing `stateAt`, `stateEventId`, `appliedThrough*` and — the consequence — `expiresAt`, so a producer that republishes a recovery every few minutes extends a closed row's retention horizon indefinitely and the row never ages out. The clearing CAS therefore carries `state: { $ne: "cleared" }` in addition to the watermark, making the second publication a `matchedCount`-0 no-op. Two accepted costs, both tested (chunk 2b Step 2, AC6): it increments **neither** `rowsCleared` nor `clearRefused` (a cleared row passes provenance, so counting a refusal would misname it), and `stateEventId` keeps naming the **first** clearing event forever. This is the same instrument as the `deliveryReference`-vs-ring entry above — a plan-lane decision recorded rather than a spec reinterpretation; if a reviewer disagrees it is a spec-lane change, not an implementation-file one.
- **Plan-writer's own, a named edge owed forward to KPR-455:** an `at` that is not a usable `Date` is substituted with the server clock and **counted** (`intakeInvalidAt`) with a warn, rather than substituted silently in a ternary. It matters because `lastAckKey` derives from the **raw** `at`, so such a caller derives a different key on every retry and a duplicated callback double-applies — exactly the residual D7's idempotence rule exists to prevent. Refusing was declined (an edge that mis-serializes a timestamp must not lose a human's acknowledgement); the counter is what makes it visible.
- **Plan-writer's own, test-surface:** the shared fixtures live in one plain module, `src/ops/testing/notifier-harness.ts`, imported by chunks 3b, 4 and 6 — never exported from a `.test.ts`, which vitest re-registers into its importer.
- **Plan-writer's own:** the ingest loop checks its budget between pages and always pays one extra bounded `findOne` for `oldestUnappliedAt` on a non-drained stop — one mechanism instead of D5's two branches.
- The cursor's no-skip guarantee holds only while KPR-454 is the sole producer into `ops_events`; a second producer is a precondition on the child that adds one, not solved here.
- A deterministically-faulting event wedges ingest until an operator intervenes; no automatic skip and no quarantine ship, and `ingestFaults` climbing at a static `cursorAt` is the signal.
- KPR-468 must not **ship** without KPR-455's inbound acknowledgement edge; the two properties that make the _merge_ honest and the residual that remains are in D11.
